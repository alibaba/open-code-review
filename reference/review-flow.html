Review flow at a glance

把一次 diff review 壓縮成一張圖：CLI 組裝 runtime，Agent 按檔案派工，Runner 在每個檔案內反覆呼叫 LLM 和 tools，最後由 collector、manifest、emitter 收尾。

diff review source-driven quick reference
一句話： ToolDef 告訴模型能呼叫什麼；Registry/Provider 決定這個呼叫真的做什麼。
  1. CLI orchestrationexecuteReviewContextWithStage 讀 template、rules、resume、LLM config。
  2. Runtime assemblyloadLLMRuntime 產生 LLM client 與 plan/main ToolDef；buildToolRegistry 綁定內建 Provider；MCP tools 追加到同一 registry。
  3. Agent inputagent.New 建立 session、manifest 與共享 llmloop.Runner。
  4. Diff preparationagent.Run 載入 git diff、建立 DiffMap、過濾檔案、估算 token budget。
  5. Per-file dispatchdispatchSubtasks 以 semaphore 限制並行；每個檔案獨立 timeout、checkpoint 和錯誤分類。
  6. Prompt renderingexecuteSubtask 將 diff、路徑、規則、background、plan guidance 填進 MAIN_TASK。
  7. Tool loopRunPerFile 呼叫 LLM，executeToolCall 執行 tool，把結果 append 回 messages，直到 task_done 或達到 stop 條件。
  8. Result deliverycode_comment 進入 CommentCollector；agent finalize session/manifest；CLI emitRunResultTo 輸出 text 或 JSON。

Harness 對照表

Harness 概念OpenCodeReview 對應責任
Prompttask_template.json + prompts/*.md定義角色、review scope、placeholder 與停止規則。
Tool schematools.json → llm.ToolDef告訴模型名稱、描述、參數 JSON schema。
Tool implementationtool.Provider + Registry把工具名稱解析成 Go 執行邏輯。
LLM adapterllm.LLMClient送出 ChatRequest，回傳 content、tool calls、usage。
Agent runnerllmloop.Runner.RunPerFile維持單檔 conversation state，處理 round、retry、compression。
State / tracesession.SessionHistory + telemetry保存 request、response、tool result、checkpoint、token 與 coverage。
Final outputCommentCollector + manifest + emitter把 finding、部分完成狀態和診斷資訊交給 CLI 或整合端。

最重要的 loop

messages = rendered MAIN_TASK
repeat until task_done or stop:
    response = LLMClient.CompletionsWithCtx(messages, MainToolDefs)
    for call in response.ToolCalls:
        result = Registry.Provider.Execute(arguments)
    messages += assistant tool-call + tool results
    maybe compress context
comments = CommentCollector.Comments()

OCR выполняет детерминированные инженерные операции (выбор файлов, разрешение
правил), а основной агент проводит само код-ревью, используя возможности
собственной LLM. На стороне OCR эндпоинт LLM не требуется.

## Когда использовать режим делегирования

Режим делегирования предназначен для AI-агентов программирования по подписке,
таких как Claude Code, Codex, Cursor, Open Code, Qoder и другие, где подписка
на LLM уже включена в основной агент. Вместо настройки отдельного эндпоинта
модели для OCR вы используете существующую квоту подписки основного агента для
проведения ревью.

Используйте режим делегирования, когда:

1. Ваш AI-агент программирования работает по подписке, и вы хотите использовать
   её квоту для код-ревью без дополнительного API-ключа или настройки модели.
2. От OCR требуется только инженерный каркас: фильтрация файлов, разрешение
   правил и логика исключений, а все рассуждения LLM выполняет основной агент.
3. Вы создаёте собственный агентный конвейер, которому нужны структурированные
   входные данные (список файлов и правила) для собственного этапа ревью.

## Предварительные требования

CLI `ocr` должен быть установлен:

```bash
which ocr || npm install -g @alibaba-group/open-code-review
```

Конфигурация LLM (`ocr config set …` или переменные окружения) не требуется:
в режиме делегирования OCR никогда не вызывает LLM на своей стороне.

## Установка навыка / команды

### Claude Code — команда

```bash
mkdir -p .claude/commands
curl -o .claude/commands/delegate-review.md \
  https://raw.githubusercontent.com/alibaba/open-code-review/main/plugins/open-code-review/claude-code/commands/delegate-review.md
```

Для полного сканирования файлов установите также команду scan:

```bash
curl -o .claude/commands/delegate-scan.md \
  https://raw.githubusercontent.com/alibaba/open-code-review/main/plugins/open-code-review/claude-code/commands/delegate-scan.md
```

### Любой агент — навык

```bash
npx skills add alibaba/open-code-review --skill open-code-review-delegate
```

Или скопируйте манифест вручную:

```bash
cp -R /path/to/open-code-review/skills/open-code-review-delegate ~/.claude/skills/
```

## Рабочий процесс

### Шаг 1. Предварительный просмотр — определить, что проверять

```bash
ocr delegate preview [--from <ref> --to <ref>] [--commit <hash>] [--exclude <patterns>]
```

Вывод содержит:

- **режим** — workspace / range / commit;
- **метаданные ссылок** — from, to, commit, merge\_base;
- **список проверяемых файлов** — пути, статусы, добавления/удаления;
- **исключённые файлы** — с причиной исключения.

Распространённые варианты вызова:

| Сценарий | Команда |
|----------|---------|
| Изменения рабочей области | `ocr delegate preview` |
| Сравнение веток | `ocr delegate preview --from main --to feature` |
| Один коммит | `ocr delegate preview -c abc123` |

### Шаг 2. Получить правила для файлов

```bash
ocr delegate rule <path1> <path2> ...
```

Передайте проверяемые пути из шага 1. Вывод группируется по содержимому правил:
файлы с одинаковым правилом находятся в одной группе, что позволяет избежать
повторений.

### Шаг 3. Получить diff

Используйте Git напрямую на основе режима и сведений о ссылках из шага 1:

**Режим диапазона** (предоставлен merge\_base):
```bash
git diff <merge_base>..<to> -- <path>
```

**Режим коммита**:
```bash
git show <commit> -- <path>
```

**Режим рабочей области**:
```bash
git diff HEAD -- <path>        # tracked files
cat <path>                     # new untracked files
```

### Шаг 4. Проверить каждый файл

Для каждого проверяемого файла:

1. Получить его diff (шаг 3).
2. Использовать подходящую группу правил (шаг 2) как контрольный список ревью.
3. Провести тщательное ревью, при необходимости исследуя контекст.

### Шаг 5. Подготовить отчёт

Классифицируйте каждое замечание по серьёзности:

- **Critical/High** — ошибки, проблемы безопасности, риски потери данных. Всегда сообщать.
- **Medium** — проблемы производительности, недостаточная обработка ошибок. Сообщать с контекстом.
- **Low** — замечания по стилю, мелкие предложения. Незаметно отбрасывать, если они не несут явной пользы.

## Полное сканирование файлов (без diff)

Описанный выше процесс проверяет diff. Когда осмысленного diff нет — при аудите незнакомой кодовой базы, каталога или набора файлов — используйте `ocr delegate scan`. Это аналог `ocr scan` для режима делегирования: он заменяет пару preview + rule одним вызовом.

```bash
ocr delegate scan [--path <каталоги-или-файлы>] [--exclude <patterns>] [--batch <strategy>]
```

Выводит:

- **батчи** — файлы, сгруппированные ровно так, как их распределил бы `ocr scan`; для каждого батча указаны его номер, ключ группировки и количество строк по файлам;
- **исключённые файлы** — с причиной исключения;
- **группы правил** — разрешённые правила ревью (можно опустить через `--no-rules`).

В отличие от `delegate preview`, эта команда работает и вне Git-репозитория: полному сканированию файлов не нужны ссылки (refs).

### Рабочий процесс

1. **Постройте план сканирования.** Сначала посмотрите `scannable_count`; если охват шире, чем нужно, сузьте его через `--path`.
2. **Проверяйте по одному батчу на субагента.** Батч — это единица диспетчеризации, рассчитанная OCR на один изолированный контекст; по возможности запускайте батчи параллельно.
3. **Читайте каждый файл целиком.** Diff отсутствует — предметом ревью является весь файл.
4. **Применяйте соответствующую группу правил** как контрольный список, при необходимости изучая вызывающий код, определения и тесты, чтобы подтвердить реальность каждой находки.
5. **Составьте отчёт** с той же классификацией по важности, что и выше, и завершите его сводкой по покрытию.

Полное сканирование выявляет намного больше кандидатов, чем ревью diff, а давно существующий код обычно написан намеренно. Отдавайте приоритет точности: сообщайте о находке только тогда, когда можете назвать её конкретное последствие.

### Флаги, специфичные для сканирования

| Флаг | Описание |
|------|----------|
| `--path <paths>` | Каталоги или файлы для сканирования через запятую (по умолчанию: весь репозиторий). |
| `--batch <strategy>` | Переопределяет группировку: `none`, `by-language`, `by-directory`. |
| `--batch-size <n>` | Максимум файлов в батче (0 — значение по умолчанию из шаблона). |
| `--no-rules` | Не включать разрешённые правила в план. |

## Справочник подкоманд

| Команда | Назначение |
|---------|---------|
| `ocr delegate preview` | Выводит проверяемые файлы и метаданные режима/ссылок. |
| `ocr delegate rule <path...>` | Разрешает правила ревью и группирует их по содержимому. |
| `ocr delegate scan` | План полного сканирования файлов: батчи и правила, diff не нужен. |

## Общие флаги

| Флаг | Описание |
|------|-------------|
| `--from <ref>` | Исходная ссылка для режима диапазона. |
| `--to <ref>` | Целевая ссылка для режима диапазона. |
| `-c, --commit <hash>` | Режим одного коммита. |
| `--repo <path>` | Корень репозитория (по умолчанию текущий рабочий каталог). |
| `--rule <path>` | Путь к пользовательскому rule.json. |
| `--exclude <patterns>` | Разделённые запятыми шаблоны исключения. |
| `-b, --background <text>` | Бизнес-контекст. |
| `-B, --background-file <path>` | Бизнес-контекст из файла Markdown (приоритет над `-b`). |

Запускайте ревью и сканирование OCR из беседы в ACP-совместимом клиенте. Адаптер
`ocr-acp` соединяет редактор с локальным CLI OCR через Agent Client
Protocol (ACP) и показывает ход выполнения, замечания и расположение файлов
прямо в беседе. Он предлагает исправления, но не изменяет файлы.

ACP — открытый протокол для связи редакторов с агентами. Клиент запускает адаптер
как отдельный локальный процесс и обменивается с ним сообщениями JSON-RPC через
stdio. Адаптер проверяет запрос, запускает `ocr review` или `ocr scan` и
преобразует структурированный вывод OCR в обновления для клиента. Движок ревью
и настройки модели OCR остаются независимыми от адаптера.

## Требования {#prerequisites}

- Установите [CLI OCR](../../installation/) и настройте
  [модель для ревью](../../configuration/). Проверьте её командой `ocr llm test`.
- Для сборки адаптера нужны исходный код с каталогом `acp/`, Git и Go 1.23+.
  Для сборки самого CLI OCR требуется Go 1.25.5+.
- Используйте клиент с поддержкой ACP v1 через stdio и настраиваемой команды агента.
  На macOS выполняются локальные тесты; Linux CI запускает тесты с детектором гонок
  и smoke-тест Python SDK. Windows использует Job Object и отменяемый stdio,
  но текущий CI только компилирует Windows-бинарники. Нативное выполнение
  и графический клиент в Windows требуют отдельной проверки.

Адаптер собирается отдельно от CLI OCR. Инструкции ниже предполагают локальную
сборку, а не готовый исполняемый файл ACP из npm-пакета OCR.

### Linux RISC-V (riscv64)

Доступна экспериментальная поддержка сборки из исходников. На Linux riscv64
выполните `make build` и `make -C acp build` из корня репозитория, затем укажите
в клиенте абсолютные пути к `dist/opencodereview` и `dist/ocr-acp`.
Текущий процесс выпуска не создаёт бинарники riscv64; задания riscv64 в CI нет.

2026-09-17 на коммите `c9279e7` с Go 1.26.5 в Docker/QEMU прошли сборка
OCR CLI и ACP, запуск бинарников и основные тесты ACP без детектора гонок.
Это проверка совместимости прежней версии, а не последней ревизии.
Бинарники с детектором гонок компилировались, но не запускались в QEMU из-за
`ThreadSanitizer: unsupported VMA range`; тест команды, запускающий такой
дочерний процесс, был исключён. Реальное оборудование RISC-V, smoke-тест
Python SDK, графические клиенты и полный набор тестов OCR CLI на этой
архитектуре пока не проверены.

## Сборка и подключение клиента {#build-and-connect-your-client}

В корне репозитория выполните:

```bash
make -C acp build
command -v ocr
```

Сборка создаёт `dist/ocr-acp`. Используйте выведенный абсолютный путь к `ocr`
в качестве значения `--ocr-binary` ниже.

Зарегистрируйте в клиенте пользовательского агента `OpenCodeReview`, выберите
транспорт ACP v1 stdio и настройте следующую команду запуска:

```bash
/absolute/path/open-code-review/dist/ocr-acp --ocr-binary /absolute/path/ocr
```

Укажите абсолютные пути обоих исполняемых файлов и рабочий каталог проекта.
Названия полей зависят от клиента; следуйте его инструкции по настройке ACP.
В новой беседе OpenCodeReview slash-команды работают без отдельной модели
разбора. Самому OCR по-прежнему нужна модель для ревью.

В Windows установите Go и Make, соберите и используйте `dist/ocr-acp.exe`.
Найдите OCR командой `Get-Command ocr` в PowerShell. В JSON используйте прямые
косые черты или экранируйте обратные. При отмене адаптер пытается отправить
CTRL_BREAK при наличии общей консоли, затем завершает оставшиеся процессы через
Job Object. Без консоли принудительное завершение может не позволить OCR вернуть частичный JSON.

## Запуск ревью или сканирования {#run-a-review-or-scan}

Отправляйте эти команды в беседе OpenCodeReview:

| Запрос | Команда |
| --- | --- |
| Проверить индексированные, неиндексированные и неотслеживаемые изменения | `/review` |
| Выполнить не более одного раунда ревью | `/review --effort low` |
| Проверить последний коммит текущей рабочей копии | `/review --commit HEAD` |
| Сравнить две существующие ссылки Git | `/review --from main --to HEAD` |
| Просканировать каталог | `/scan --path internal/agent` |
| Просканировать несколько путей | `/scan --path internal/agent,internal/config` |

Замените ссылки Git и пути из примеров значениями вашего проекта. Для ревью
нужен репозиторий Git; расположение замечаний определяется относительно его
корня. Сканирование использует рабочий каталог сеанса. `--effort low` запускает
не более одного раунда ревью, `medium` — двух, `high` — трёх. Если новых замечаний нет,
ревью может закончиться раньше. Если флаг не указан, применяется конфигурация OCR.
Меньшее число раундов может привести к пропуску проблем: выбирайте баланс
скорости и качества в зависимости от задачи.

Введите `/` в клиенте с поддержкой подсказок команд ACP, чтобы увидеть команды
и их аргументы. Динамического автодополнения веток и путей нет. Если клиент
прикрепляет ссылки на локальные файлы, отправьте их вместе с `/scan`, без
`--path`. Ссылки нельзя сочетать с `/review` или явными путями сканирования.
Неподдерживаемые и неоднозначные ссылки отклоняются, а не расширяют область
сканирования автоматически.

Адаптер принимает определённый набор параметров CLI, а не передаёт произвольные
параметры напрямую:

- Ревью: `--commit`, `--from`, `--to`, `--effort`, `--no-filter`,
  `--background`, `--background-file`.
- Сканирование: `--path`, `--batch`, `--no-plan`, `--no-dedup`, `--no-summary`,
  `--background`.

Используйте `/review` для всего набора изменений; `--staged` не поддерживается.
В командах беседы нельзя задавать параметры вывода, такие как `--format` и
`--audience`, или переопределения `--repo`, `--model` и `--provider`.
Настраивайте модель для ревью средствами самого OCR.

## Запросы на естественном языке {#enable-natural-language-requests}

Модель разбора преобразует запросы на естественном языке в команды ревью или
сканирования либо задаёт уточняющие вопросы. Она настраивается отдельно от
модели OCR для ревью; выбор собственной модели клиента не настраивает ни одну из них.

Добавьте следующие переменные окружения в объект `env` агента, заменив
значения модели и ключа данными вашего провайдера:

```json
{
  "OCR_ACP_PARSER_PROVIDER": "openai",
  "OCR_ACP_PARSER_MODEL": "YOUR_TOOL_CALLING_MODEL",
  "OCR_ACP_PARSER_API_KEY": "YOUR_PARSER_API_KEY"
}
```

В примере используется протокол OpenAI-совместимого Chat Completions. Для
протокола Anthropic Messages укажите `anthropic`. При использовании совместимого
шлюза также задайте его базовый URL API в `OCR_ACP_PARSER_BASE_URL`. Храните
учётные данные в локальных настройках или передавайте их через окружение процесса
агента; не добавляйте их в общие настройки проекта в репозитории. Графическое
приложение может не наследовать переменные окружения, заданные в терминале.

Правила пути в базовом URL зависят от протокола:

| Протокол | Пример `OCR_ACP_PARSER_BASE_URL` | Адрес запроса |
| --- | --- | --- |
| `openai` | `https://gateway.example/v1` | `https://gateway.example/v1/chat/completions` |
| `anthropic` | `https://gateway.example` | `https://gateway.example/v1/messages` |

Можно также указать полный адрес, оканчивающийся соответственно на `/chat/completions` или
`/v1/messages`: этот суффикс не добавляется повторно. Базовый URL Anthropic, оканчивающийся
на `/v1`, даст путь `/v1/v1/messages`; указывайте путь согласно API вашего шлюза.

| Переменная окружения | Флаг запуска | Назначение |
| --- | --- | --- |
| `OCR_ACP_PARSER_PROVIDER` | `--parser-provider` | `openai` или `anthropic` |
| `OCR_ACP_PARSER_MODEL` | `--parser-model` | Модель с поддержкой вызова инструментов |
| `OCR_ACP_PARSER_BASE_URL` | `--parser-base-url` | Необязательное переопределение базового URL API |
| `OCR_ACP_PARSER_API_KEY` | Нет | Ключ API модели разбора; только через окружение |

Флаги запуска имеют приоритет над соответствующими переменными окружения.
Модель разбора не читает конфигурацию OCR и переменные `OCR_LLM_*`. Здесь
поддерживаются протоколы `openai` и `anthropic`; `openai-responses` и
`anthropic-bedrock` не поддерживаются.

В запросах разбора Anthropic режим Thinking явно отключается для обязательного
вызова инструмента `submit_intent`. Настройки Thinking модели OCR для ревью
при этом не меняются.

После настройки модели разбора начните новую беседу и попробуйте:

```text
Проверь изменения в моём рабочем каталоге.
Проверь последний коммит текущей рабочей копии.
Просканируй internal/agent на наличие потенциальных ошибок.
```

Если запрос неоднозначен, ответьте на уточняющий вопрос до начала выполнения.
Модели предписано задавать вопросы и давать пояснения на вашем языке;
фиксированные сообщения проверки и подписи отчёта остаются на английском.
Если модель разбора недоступна, slash-команды продолжают работать. Неполная
конфигурация модели разбора приводит к явной ошибке при запуске.

«Последний коммит текущей рабочей копии» соответствует `/review --commit HEAD`.
Сеанс хранит один незавершённый запрос на уточнение, который может содержать несколько совместимых
полей. Последовательные уточнения сохраняют известные значения, а явно указанные новые значения
заменяют старые. Поля разных типов ревью не смешиваются. После завершения или отмены состояние
очищается и не восстанавливается в другом сеансе.

## Результаты и отмена {#read-results-and-cancel-work}

Прогресс использует существующие журналы CLI OCR и итоговый JSON; менять CLI не требуется. Отображаются последнее сообщённое действие и общее время выполнения. Этапы групп, их длительность и ожидание ответа модели не вычисляются предположительно.

Одна запись **OCR review** или **OCR scan** показывает текущую активность и время,
измеренное адаптером. Раскройте её, чтобы увидеть **Command:**, рабочий каталог и
ограниченный по размеру текстовый журнал. Диагностические строки остаются в деталях
и не заменяют заголовок прогресса. Команда и журнал не дублируются в тексте беседы;
начальное состояние раскрытия определяет клиент.

Итоговый отчёт начинается со статуса завершения, количества файлов и замечаний,
а также распределения по серьёзности. Заголовок каждого замечания содержит номер,
серьёзность и расположение файла; далее идут категория, объяснение и блоки кода
с указанием языка. Предложения явно помечены как неприменённые. Замечания появляются
только один раз в итоговом сообщении. Допустимые расположения становятся ссылками;
несуществующие файлы, строки вне диапазона и пути за пределами рабочего корня
остаются обычным текстом. Отображение и переходы зависят от версии клиента.

Сведения о частичных сбоях и достижении лимита бюджета сохраняются. В конце отчёта
показаны доступные суммарные токены и время, сообщённое OCR. Детали выполнения также
содержат число вызовов инструментов и входные, выходные и кешированные токены,
если OCR их предоставил. Отсутствующие значения не выдумываются. Локальный таймер
может отличаться от времени OCR; сумма токенов охватывает все запросы к модели,
а не только вновь сгенерированный ответ.

Чтобы остановить выполняющийся запрос, воспользуйтесь отменой в клиенте.
Адаптер отменит работу и дождётся завершения управляемых процессов. Чтобы
ограничить длительность всего запроса, включая разбор, добавьте
`"--turn-timeout", "10m"` в массив `args` агента. Значение по умолчанию — `0`;
оно отключает общий тайм-аут. У разбора есть отдельный лимит, по умолчанию
15 секунд. При превышении времени адаптер предложит повторить запрос.

## Устранение неполадок {#troubleshooting}

| Симптом | Что проверить |
| --- | --- |
| Агент не запускается | Проверьте оба абсолютных пути к исполняемым файлам и права на выполнение. Выполните `ocr llm test` для проверки конфигурации OCR; удалите неполные настройки модели разбора или задайте все необходимые значения. |
| Slash-команды работают, запросы на естественном языке — нет | Настройте отдельные переменные окружения `OCR_ACP_PARSER_*`. Проверьте провайдера, модель, ключ и URL шлюза. |
| Истёк тайм-аут разбора естественного языка | Разбор по умолчанию ограничен 15 секундами; OCR на этом этапе ещё не запущен. Изучите этап запроса, HTTP-статус и ответ провайдера в диагностике. Увеличение `--turn-timeout` не продлевает собственный тайм-аут разбора. Повторите запрос или используйте `/review`, `/scan` без модели разбора. |
| Команда или флаг отклонены | Используйте поддерживаемые параметры из списка выше. Вместо `/review --path` используйте `/scan --path`; для ревью коммита или диапазона указывайте существующие ссылки Git. |
| Ревью завершается ошибкой или возвращает частичный результат | Раскройте OCR review/scan для диагностики и прочитайте итоговые сведения об ошибке. Проверьте конфигурацию модели OCR и доступность провайдера. |
| Расположение в результате недоступно для перехода | Убедитесь, что файл существует внутри корня операции и диапазон строк корректен. Отображение только текста в остальных случаях предусмотрено намеренно. |
| Задача выполняется слишком долго | Отмените её, изучите сведения о ходе выполнения или задайте общий тайм-аут. Для ревью `--effort low` уменьшает число раундов. |
| После пересборки сохраняется старое поведение | Проверьте путь к исполняемому файлу в настройках и начните новую беседу с агентом. Перезапустите агент или клиент, если он продолжает использовать старый процесс. |

При проблемах с подключением изучите журналы ACP клиента и stderr адаптера.
Перед передачей журналов удалите учётные данные и конфиденциальные сведения.

## Обновление и границы поддержки {#upgrade-and-support-boundaries}

Обновите исходный код, снова выполните `make -C acp build` и начните новую
беседу OpenCodeReview. Активные процессы и старые сообщения не перезагружаются.
Восстановление сеанса не поддерживается; новая беседа начинается без сохранённых
незавершённых уточнений.

Адаптер использует локальный транспорт stdio. Транспорт HTTP, дополнительные
корни рабочей области, автоматическое редактирование файлов и запросы
с изображениями или аудио не поддерживаются. Другие клиенты ACP требуют
собственных проверок совместимости; успешные тесты протокола не подтверждают
поведение интерфейса каждого клиента.

Зарегистрируйте OCR как вызываемый навык, чтобы агентный фреймворк мог
запускать его с правильными флагами и процедурой проверки замечаний — без
необходимости заново реализовывать всё это на
вызывающей стороне.

## Что поставляется в репозитории

В репозитории находится манифест SKILL по пути
[`skills/open-code-review/SKILL.md`](https://github.com/alibaba/open-code-review/blob/main/skills/open-code-review/SKILL.md).
Он определяет запуск OCR, проверку замечаний, отчёт о неопределённости и
исправления по запросу. Каталог навыка также содержит помощник для ревью
GitHub PR; устанавливайте весь каталог, а не только SKILL.md.

## Установка

### Вариант 1: `npx skills add` (рекомендуется)

Выполните команду внутри проекта, в котором должен быть доступен навык:

```bash
npx skills add alibaba/open-code-review --skill open-code-review
```

Команда устанавливает каталог навыка из
[реестра навыков](https://github.com/alibaba/open-code-review/blob/main/skills/open-code-review/SKILL.md)
и помещает его в проект, чтобы любой агент программирования, поддерживающий
соглашение о навыках, обнаружил его при следующем запуске. Чтобы обновить
навык до последней версии, выполните команду повторно.

> **Требования:** нативному режиму нужен локально настроенный провайдер модели
> OCR. Не вставляйте учётные данные в разговор. Если `ocr` отсутствует, инструкции
> по устранению ошибок описывают установку через
> `npm install -g @alibaba-group/open-code-review`. Только режим GitHub PR также
> требует Python 3 и авторизованный `gh`. См. [Конфигурацию](../../configuration/).

### Вариант 2: копирование вручную (для всей системы)

Если вы предпочитаете установить навык глобально, а не отдельно для каждого
проекта, скопируйте каталог в директорию навыков:

```bash
mkdir -p ~/.claude/skills
cp -R /path/to/open-code-review/skills/open-code-review ~/.claude/skills/
```

После этого навык будет доступен каждому проекту на компьютере.

## Что делает навык {#what-the-skill-does}

SKILL.md — это промпт: когда вызывающий агент загружает его, агент сам
выполняет описанные шаги. Полный процесс по одному запросу
`/open-code-review` (или его эквиваленту) выглядит так:

1. **Извлечение бизнес-контекста.** Проверить цель ревью (коммиты, ветку,
   рабочую копию) и сформировать короткую строку `--background`.
2. **Запуск запрошенного ревью.** Для локального ревью сразу выполнить
   `ocr review --audience agent --background "…"`, добавив `--commit` или
   `--from`/`--to` для закоммиченных изменений. Обычный путь не требует
   предварительных проверок установки или подключения. Новое ревью коммита
   или диапазона по умолчанию добавляет `--analysis` и использует JSON, если
   не запрошен другой формат. Анализ не добавляется для рабочей копии,
   предварительного просмотра, возобновления, SARIF или явного отказа от анализа.
   После ошибки сначала выяснить причину, затем повторять вызов.
   Для номера или URL GitHub PR использовать установленный помощник
   `python3 "$SKILL_DIR/scripts/review_pr.py" <id-or-url>`. Номер выбирает
   репозиторий `gh` по умолчанию для текущей рабочей копии; в форке это может
   быть upstream. Сообщить URL PR, проверенные ревизии, актуальность снимка и путь к результатам.
3. **Проверка и отчёт.** Сверить каждое замечание с проверяемым кодом, включая
   замечания низкой важности. Разделить их на **Reproduced (воспроизведено)** и
   **Uncertain (не установлено)**, сохраняя важность OCR и порядок внутри каждой
   группы. Пропускать замечание только при конкретном опровергающем свидетельстве,
   а не из-за одной неопределённости. Сохранить исходный результат и сообщить
   покрытие Review и пробелы. При совместном запуске отдельно отобразить Markdown
   Analysis, различая статус исполнения и оценку полноты, данную моделью.
4. **Исправление по запросу.** Вносить безопасные, проверенные исправления только
   при запросе на редактирование, уделяя приоритет замечаниям critical, high и medium.
   Запрос только на ревью не разрешает менять код. В режиме PR сохранять снимок
   до явного согласия пользователя на очистку; отчёты после очистки остаются.

Полный промпт, включая требования к проверке, отчётности, ограничения режима PR и подводные
камни, находится в файле
[`skills/open-code-review/SKILL.md`](https://github.com/alibaba/open-code-review/blob/main/skills/open-code-review/SKILL.md).
Измените локальную копию, если хотите скорректировать описанное поведение
(например, всегда запрашивать разрешение перед исправлением).

## Anthropic Agent SDK

Укажите установленный навык при инициализации SDK:

```python
from anthropic_agent_sdk import Agent

agent = Agent(
    skill_paths=["/path/to/open-code-review/skills/open-code-review"],
)

agent.run("Review my staged changes — focus on race conditions.")
```

SDK загружает промпт SKILL.md, после чего агент выполняет процесс из раздела
[Что делает навык](#what-the-skill-does), включая разбор ошибок вызова и просьбу
настроить учётные данные локально, если они необходимы.

## Другие агентные фреймворки

Любой фреймворк с возможностью регистрации внешних навыков может использовать
SKILL.md: это обычный Markdown с frontmatter. Если фреймворк ожидает другую
схему, тело Markdown всё равно можно использовать как шаблон промпта.

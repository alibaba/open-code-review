Нативный плагин объединяет дополнительные правила ревью в локальном каталоге.
OCR копирует каталог в пользовательский снимок. Включённые плагины добавляют
правила в `ocr review` и `ocr scan` во всех репозиториях. Файлы пакета читаются как данные.

## Установка и проверка {#install-and-inspect}

Из рабочего каталога исходников OCR установите встроенный пример:

```bash
ocr plugin install ./examples/ocr-plugins/review-checklist
ocr plugin list
ocr plugin show review-checklist
ocr plugin enable review-checklist
ocr rules check src/main.go
```

По умолчанию установленный плагин выключен. Флаг `--enable` включает его при
установке. `ocr rules check` показывает ID, версию, путь пакета правил и шаблон
каждого совпавшего плагина, а затем объединённый текст правил. Все подкоманды
плагинов поддерживают `--json`, например `ocr plugin list --json`.

Перед включением проверьте текст правил: он попадёт в промпт модели для ревью.
Источником установки служит локальный каталог с файлом `ocr-plugin.json`.
URL, ссылки на репозитории GitHub и архивы ZIP или tar.gz не принимаются.

## Формат пакета {#package-format}

Пример состоит из трёх файлов:

```text
review-checklist/
  ocr-plugin.json
  rules.json
  checklist.md
```

`ocr-plugin.json`:

```json
{
  "schema_version": 1,
  "id": "review-checklist",
  "name": "Review Checklist",
  "version": "1.0.0",
  "description": "Additional review checks for error handling and resource ownership.",
  "rules": ["rules.json"],
  "requires": {"features": ["rules"]}
}
```

| Поле | Требования |
|---|---|
| `schema_version` | Обязательное; значение `1`. |
| `id` | Обязательное; 1–64 строчных ASCII-буквы, цифры, `.`, `_`, `-`. Начинается и заканчивается буквой или цифрой. Зарезервированные имена Windows запрещены. |
| `name`, `version` | Обязательные строки, содержащие не только пробелы. |
| `description` | Необязательное описание для `ocr plugin show`. |
| `rules` | Обязательный непустой упорядоченный список различных относительных путей к `.json` внутри пакета. |
| `requires.ocr_min_version` | Необязательная полная семантическая версия, например `1.0.0`; сравнивается с версией сборки OCR. |
| `requires.features` | Необязательный список требуемых возможностей; поддерживается значение `rules`. |
| `metadata` | Необязательный JSON-объект, сохраняемый без интерпретации и исполнения. |

Неизвестные поля манифеста и повторяющиеся JSON-ключи отклоняются. Совместимость
проверяется при установке, включении и загрузке включённых плагинов. Сборка `dev` не может
удовлетворить `ocr_min_version`; для пакетов под такую сборку опустите это требование.

`rules.json`:

```json
{
  "rules": [
    {
      "path": "**/*.{go,js,mjs,ts,tsx,py}",
      "rule": "checklist.md"
    }
  ]
}
```

`checklist.md` содержит указания для ревью:

```text
Check error propagation, cleanup, and resource ownership.
Report only concrete failure paths in the changed code.
Verify the relevant caller and explain the trigger and user-visible consequence.
```

В `rule` также можно написать текст напрямую. Ссылка на Markdown разрешается
относительно файла пакета правил и должна оставаться внутри плагина. В путях
используйте `/`. Поля `include` и `exclude` задавайте в правилах проекта или
пользователя: непустые списки этих полей в плагине отклоняются.

## Объединение правил {#how-rules-combine}

Сначала OCR разрешает базовые правила в прежнем порядке: `--rule`, проект,
глобальные, системные. Затем добавляет включённые плагины по возрастанию ID и
в порядке `rules` каждого манифеста. В каждом пакете правил применяется первое
совпадение, поэтому несколько пакетов могут дополнять указания для одного файла.

Правила плагинов всегда добавляются. Поле `merge_system_rule` в пакете не влияет
на результат. Файлы для ревью по-прежнему выбирают существующие фильтры. Шаблоны,
фильтрация и базовые приоритеты описаны в разделе [Правила ревью](../review-rules/).

## Выключение, замена и удаление {#disable-replace-and-remove}

```bash
ocr plugin disable review-checklist
ocr plugin remove review-checklist
ocr plugin install ./examples/ocr-plugins/review-checklist --enable
```

Перед заменой удалите установленный ID. Изменения исходного каталога вступят
в силу после повторной установки. Состояние хранится в
`~/.opencodereview/plugins/state.json`, снимки — в `plugins/packages/`.
Удаление снимает регистрацию плагина и сохраняет снимки для уже запущенных ревью.

Идентификатор конфигурации для возобновления включает манифесты включённых
плагинов и содержимое пакетов. Повторная установка того же содержимого сохраняет
его; изменение содержимого исключает повторное использование результатов,
полученных с прежней конфигурацией плагинов.

Ограничения пакета: 64 MiB и 4 096 элементов, включая каталоги. Манифест ограничен
1 MiB, каждый JSON-пакет правил при загрузке — 512 KiB. Символьные ссылки,
специальные файлы, конфликты имён без учёта регистра, зарезервированные имена
Windows и пути за пределами пакета отклоняются. Не изменяйте снимки: редактируйте
исходный каталог и устанавливайте пакет заново.

Сводка команд: [Справочник CLI](../cli-reference/#ocr-plugin).

Передайте OCR критерии приёмки изменения, чтобы он проверял бизнес-логику вместе
с дефектами кода. Рекомендуемый рабочий процесс — сохранить требования в
локальном Markdown-файле и передать их через `--background-file`.

## Файл требований для изменения

Для отдельного изменения подготовьте краткий локальный Markdown,
например `docs/requirements/checkout.md`:

```markdown
# Checkout requirements

Scope: src/checkout/**
Review changes against these criteria and cite the requirement ID in findings.

- PAY-1: Reject checkout when the cart is empty.
- PAY-2: Calculate the total on the server; never trust a client-supplied total.
- PAY-3: A repeated idempotency key must not create a second charge.

Out of scope: refunds and subscription billing.
```

Настройте OCR, убедитесь, что `main` доступна локально, и выполните из корня
репозитория:

```bash
ocr review --from main --to HEAD --background-file docs/requirements/checkout.md
```

`--background-file` задаёт контекст для всего ревью. Относительные пути
отсчитываются от **корня репозитория**, даже при запуске OCR из подкаталога;
абсолютные пути тоже поддерживаются. Если указан и `--background`, файл имеет
приоритет, а текст из флага игнорируется. Сокращайте контекст: после очистки
содержимого OCR предупреждает при превышении 2 000 символов и отклоняет более
8 000. Размер входного файла не должен превышать 1 MiB, а после очистки он не
должен быть пустым.

## Требования из внутренней базы знаний

Для внутренней базы знаний экспортируйте нужные требования, ограничения и
критерии приёмки в краткий локальный Markdown и передайте его через
`--background-file`. Само по себе упоминание имени файла или удалённой ссылки
в тексте background не загружает документ и не открывает ссылки из него
автоматически. Включите сами критерии и сверяйте замечания со спецификацией
и тестами.

## Ограничения

OCR воспринимает требования как контекст одного ревью. Сейчас нет специального
способа связать справочные документы с модулем или каталогом независимо от
правил ревью: правила по путям выбирают текст правила для совпавших файлов и
потому не являются механизмом прикрепления справочных материалов. Если сценарий
использования базы знаний созреет, для него можно будет спроектировать
отдельную поддержку.

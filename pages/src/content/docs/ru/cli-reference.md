Полный справочник по всем подкомандам, флагам и кодам завершения `ocr`.

## Общее использование

```text
OpenCodeReview — CLI для код-ревью с ИИ

Использование:
  ocr [command]

Команды:
  review, r    Запустить код-ревью
  rules        Просмотреть и отладить правила ревью
  config       Управлять настройками конфигурации
  llm          Служебные команды LLM
  viewer       Запустить просмотр сессий WebUI
  session, sessions  Вывести и просмотреть сохранённые сессии ревью
  version      Показать информацию о версии

Примеры:
  ocr review --from master --to dev        Проверить диапазон diff
  ocr review --commit abc123               Проверить один коммит
  ocr config provider                      Интерактивно настроить провайдер
  ocr config model                         Интерактивно выбрать модель
  ocr config set llm.model opus-4-6        Задать значение конфигурации
  ocr llm test                             Проверить подключение к LLM
  ocr llm providers                        Вывести встроенные провайдеры
  ocr session list                         Вывести сохранённые сессии ревью
  ocr version                              Показать сведения о версии

Используйте "ocr review -h" для дополнительных сведений о ревью.
Используйте "ocr rules -h" для дополнительных сведений о правилах.
Используйте "ocr config" для дополнительных сведений о конфигурации.
Используйте "ocr llm" для дополнительных сведений об утилитах LLM.
Используйте "ocr session -h" для дополнительных сведений о просмотре сессий.

GitHub: https://github.com/alibaba/open-code-review
```

## Краткая сводка команд

| Команда | Алиас | Назначение |
|---|---|---|
| `ocr review` | `ocr r` | Запускает код-ревью и выводит комментарии. |
| `ocr rules check <file>` | — | Показывает, какое правило применяется к пути файла и откуда оно получено. |
| `ocr config set <key> <value>` | — | Сохраняет значение конфигурации в `~/.opencodereview/config.json`. |
| `ocr config unset custom_providers.<name>` | — | Удаляет пользовательский провайдер (очищает активные `provider`/`model`, если он был активен). |
| `ocr config provider` | — | Интерактивный TUI для настройки провайдера. |
| `ocr config model` | — | Интерактивный TUI для выбора модели. |
| `ocr llm test` | — | Отправляет небольшой запрос чата для проверки настроенной конечной точки. |
| `ocr llm providers` | — | Выводит все встроенные LLM-провайдеры. |
| `ocr session list` | `ocr sessions list`, `ocr session ls` | Выводит сохранённые сессии ревью. |
| `ocr session show <id>` | `ocr sessions show <id>` | Показывает одну сессию и её контрольные точки по файлам. |
| `ocr viewer` | — | Запускает локальный веб-интерфейс для прошлых сессий ревью (`localhost:5483`). |
| `ocr version` | — | Выводит версию, коммит, платформу, дату сборки и URL GitHub. |

`ocr` и `ocr -h` выводят использование верхнего уровня. Каждая подкоманда также принимает `-h` / `--help`.

## `ocr review`

Основная команда. Определяет Git diff, запускает подагентов для каждого файла, собирает комментарии ревью и выводит их.

### Синтаксис

```text
ocr review [flags]
ocr r      [flags]   (alias)
```

Если флаги не переданы, OCR работает в **режиме рабочей области** — выполняет ревью всех проиндексированных, непроиндексированных и неотслеживаемых изменений в репозитории текущего каталога.

### Флаги

| Флаг | Короткий | По умолчанию | Описание |
|---|---|---|---|
| `--repo <path>` | — | текущий каталог | Корень Git-репозитория. |
| `--from <ref>` | — | — | Исходная ссылка, с которой начинается diff (например, `main`). |
| `--to <ref>` | — | — | Целевая ссылка, на которой заканчивается diff (например, `feature-branch`). При задании OCR вычисляет `merge-base(from, to)..to`. |
| `--commit <sha>` | `-c` | — | Один коммит для ревью (в сравнении с родительским). |
| `--preview` | `-p` | `false` | Запускает конвейер фильтрации, но пропускает LLM. Выводит список файлов и причины исключения. |
| `--resume <session-id>` | — | — | Возобновляет совместимую предыдущую сессию ревью диапазона или коммита. |
| `--format <fmt>` | `-f` | `text` | `text` (для чтения человеком) или `json` (машиночитаемый массив комментариев). |
| `--audience <who>` | — | `human` | `human` выводит строки прогресса; `agent` подавляет stdout и выводит только итоговую сводку / JSON. |
| `--background <text>` | `-b` | — | Необязательные требования / бизнес-контекст, добавляемые в подсказки плана и основной задачи. |
| `--concurrency <n>` | — | `8` | Максимальное число файлов, ревью которых выполняется параллельно. |
| `--timeout <minutes>` | — | `10` | Лимит времени на файл. `0` отключает тайм-аут. |
| `--rule <path>` | — | — | Путь к пользовательскому JSON-файлу правил ревью. Переопределяет `rule.json` уровня проекта и глобальный. |
| `--max-tools <n>` | — | значение шаблона | Максимальное число раундов вызовов инструментов на файл. `0` использует значение шаблона (`30`); значения 1–9 повышаются до `10`; любое значение `≥ 10` переопределяет значение шаблона (даже если меньше `30`). |
| `--model <name>` | — | — | Переопределяет выбранную LLM-модель для этого ревью (например, `claude-opus-4-6`). |
| `--max-git-procs <n>` | — | `16` | Максимальное число одновременных подпроцессов git. |
| `--tools <path>` | — | встроенные | Путь к пользовательскому JSON-файлу конфигурации инструментов. Переопределяет встроенные определения инструментов. |

> Флаги режимов взаимоисключающие: передайте либо `--from`/`--to`, либо `--commit`, либо ни одного из них (режим рабочей области). Их смешивание приводит к ошибке.
> `--resume` поддерживает только ревью диапазона или коммита и не может сочетаться с `--preview`.

### Режимы

#### Режим рабочей области (по умолчанию)

```bash
ocr review
```

OCR собирает изменения рабочего дерева двумя командами git:

- отслеживаемые изменения через `git diff HEAD` (проиндексированные и непроиндексированные вместе относительно `HEAD`; если результат пуст, OCR использует `git diff --staged`);
- неотслеживаемые файлы через `git ls-files --others --exclude-standard`: они читаются с диска и считаются добавлением целого файла.

Обычно это нужно перед коммитом. Выбирайте файлы для индексации, если хотите сузить область ревью.

#### Режим диапазона

```bash
ocr review --from main --to feature-branch
```

OCR вычисляет `merge-base(main, feature-branch)..feature-branch`, поэтому вы видите только diff, *внесённый* веткой функциональности, а не несвязанные изменения, попавшие в `main` после создания ветки.

#### Режим коммита

```bash
ocr review --commit abc123
ocr review -c abc123
```

Выполняет ревью diff, созданного `git show abc123` (то есть изменений, внесённых этим коммитом).

### Возобновление прерванного ревью

Каждый запуск `ocr review` сохраняет локальный журнал сессии в `~/.opencodereview/sessions/`. Успешный текстовый вывод содержит только результаты ревью и не выводит ID сессии; используйте `ocr session list/show` для поиска сохранённых сессий или `--format json`, чтобы включить `session_id` в машиночитаемый вывод. Если ревью диапазона или коммита прервано, выведите сохранённые сессии и возобновите подходящую для той же цели ревью:

```bash
ocr session list
ocr session show <session-id>
ocr review --from main --to feature-branch --resume <session-id>
ocr review --commit abc123 --resume <session-id>
```

Возобновление намеренно строгое:

- ревью рабочей области нельзя возобновить;
- ревью диапазона должно использовать те же `--from` и `--to`;
- ревью коммита должно использовать тот же `--commit`;
- `--preview` и `--resume` нельзя использовать вместе.

### Вывод

#### Текст (по умолчанию, `--audience human`)

Строки прогресса выводятся во время ревью, затем следует блок для каждого комментария (приглушённый заголовок с Unicode-линией `path:start-end`, текст комментария с переносом на 100 столбцах и — при наличии — цветной встроенный diff предложенной замены). В конце в stdout выводится сводка запуска:

```
[ocr] Изменено файлов: 17, проверяется 9 в /path/to/repo
[ocr] Пропуск image.png — отфильтрован правилами пути/расширения
[ocr]   ▶ file_read "src/foo.go"
[ocr]   ✔ file_read (12ms)
[ocr] План для src/foo.go завершён
…

─── src/foo.go:42-47 ───
Одновременный доступ к map без блокировки — используйте sync.RWMutex.

- m[k] = v
+ mu.Lock(); defer mu.Unlock(); m[k] = v

…
[ocr] Итог: проверено файлов: 9, комментариев: 14, использовано ~21344 токенов (вход: ~18012, выход: ~3332), прошло 1m12s
```

#### Текст (агент, `--audience agent`)

Вывод комментариев идентичен, но строки прогресса подавляются внутренним настраиваемым stdout writer ([`internal/stdout`](https://github.com/alibaba/open-code-review/blob/main/internal/stdout/stdout.go)). Используйте в CI или при передаче вывода другому агенту.

#### JSON

```bash
ocr review --format json --audience agent
```

```json
{
  "status": "success",
  "summary": {
    "files_reviewed": 9,
    "comments": 1,
    "total_tokens": 21344,
    "input_tokens": 18012,
    "output_tokens": 3332,
    "elapsed": "1m12s"
  },
  "comments": [
    {
      "path": "src/foo.go",
      "content": "Одновременный доступ к map без блокировки — используйте sync.RWMutex.",
      "start_line": 42,
      "end_line": 47,
      "existing_code": "m[k] = v",
      "suggestion_code": "mu.Lock(); defer mu.Unlock(); m[k] = v",
      "thinking": "На строке 42 map …"
    }
  ]
}
```

Поля верхнего уровня:

| Поле | Примечания |
|---|---|
| `status` | `success`, `completed_with_warnings`, `completed_with_errors` или `skipped`. |
| `message` | Необязательное. Понятная человеку сводка, например `"No comments generated. Looks good to me."`. |
| `summary` | Необязательное. Итоги запуска: `files_reviewed`, `comments`, `total_tokens`, `input_tokens`, `output_tokens`, `cache_read_tokens` (omitempty), `cache_write_tokens` (omitempty), `elapsed`. Не включается для запусков `skipped`. |
| `comments` | Присутствует всегда, но может быть пустым. Поля каждого комментария показаны в примере выше. |
| `warnings` | Необязательное. Присутствует при сбое одного или нескольких подагентов; каждая запись описывает затронутый файл и ошибку. |
| `session_id` | Необязательное. Присутствует в сохранённых запусках ревью; передайте его в `ocr review --resume <session-id>` при повторе совместимого ревью диапазона или коммита. |
| `resume` | Необязательное. Присутствует в возобновлённых запусках с `resumed_from`, `reused_files`, `rerun_files`, `previous_model` и `current_model`. |

Если для ревью нет подходящих файлов, режим JSON выводит оболочку `skipped`, чтобы вызывающая сторона различала «нет изменений» и «нет замечаний»:

```json
{
  "status": "skipped",
  "message": "Поддерживаемые файлы не изменились.",
  "comments": []
}
```

### Коды завершения

| Код | Значение |
|---|---|
| `0` | Ревью завершено (возможно без комментариев или с некритическими предупреждениями). |
| `1` | Критическая ошибка: неверные флаги, невозможно определить конечную точку LLM, сбой всех подагентов по файлам и т. д. Текст ошибки выводится в stderr. |

Некритические предупреждения (сбой одного подагента, превышение файлом порога токенов и т. д.) выводятся непосредственно в текстовом режиме; в режиме JSON они добавляются в массив `warnings`.

## `ocr session`

Выводит и просматривает локальные журналы сессий ревью из `~/.opencodereview/sessions/`. Используйте команду, чтобы найти ID сессии, проверить состояние контрольных точек файлов и возобновить прерванное ревью диапазона или коммита.

```text
ocr session <sub-command>
ocr sessions <sub-command>   (alias)

Подкоманды:
  list, ls    Вывести недавние сессии ревью текущего репозитория
  show <id>   Показать метаданные одной сессии и элементы по файлам
```

### `ocr session list`

```bash
ocr session list
ocr session list --limit 50
ocr session list --json
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--repo <path>` | текущий каталог | Репозиторий, сессии которого нужно вывести. |
| `--json` | `false` | Выводит сводки сессий как JSON. |
| `--limit <n>` | `20` | Ограничивает число выводимых сессий. Используйте `0` для снятия ограничения. |

### `ocr session show`

```bash
ocr session show <session-id>
ocr session show --json <session-id>
ocr session show --repo /path/to/repo <session-id>
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--repo <path>` | текущий каталог | Репозиторий, сессию которого нужно просмотреть. |
| `--json` | `false` | Выводит метаданные сессии и элементы по файлам как JSON. |

## `ocr rules`

Просмотр правил. Есть ровно одна подкоманда:

```text
ocr rules check [flags] <file-path>

Флаги:
  --repo <path>    Корень Git-репозитория (по умолчанию: текущий каталог)
  --rule <path>    Путь к пользовательскому JSON-файлу правила
```

Для указанного пути файла OCR:

1. Проходит цепочку правил из четырёх уровней (пользовательский → проект → глобальный → системный).
2. Выбирает первое совпадение.
3. Выводит **исходный уровень**, совпавший **glob-шаблон** и итоговый **текст правила**.

```bash
$ ocr rules check src/main/java/com/example/Foo.java
Файл: src/main/java/com/example/Foo.java
Источник: встроенное системное
Шаблон: **/*.java
Правило:
────────────────────────────────────────
<содержимое internal/config/rules/rule_docs/java.md>
────────────────────────────────────────
```

Полезно для отладки вопроса «почему не срабатывает моё пользовательское правило?» — полное описание приоритетов см. в [Правила ревью](../review-rules/).

## `ocr config`

Сохраняет ключи в `~/.opencodereview/config.json` и предоставляет интерактивные TUI для настройки. Четыре подкоманды:

```text
ocr config set <key> <value>
ocr config unset custom_providers.<name>   Удалить пользовательский провайдер
ocr config provider                        Интерактивно настроить провайдер
ocr config model                           Интерактивно выбрать модель
```

- **`set`** — записывает одно значение конфигурации без интерактивного режима.
- **`unset`** — удаляет пользовательский провайдер. Поддерживается только `custom_providers.<name>`. Если удалённый провайдер был активен, `provider` и `model` очищаются (запустите `ocr config provider`, чтобы выбрать новый).
- **`provider`** — запускает интерактивный TUI настройки провайдера (без дополнительных аргументов; для неинтерактивной настройки используйте `ocr config set provider <name>`).
- **`model`** — запускает интерактивный TUI выбора модели (без дополнительных аргументов; для неинтерактивной настройки используйте `ocr config set model <name>`).

Полный справочник ключей, схемы и примеры см. в разделе [Конфигурация](../configuration/).

## `ocr llm`

Служебные команды LLM. Две подкоманды:

```text
ocr llm <sub-command>

Подкоманды:
  test         Отправить тестовый диалог настроенной LLM-модели
  providers    Вывести все встроенные LLM-провайдеры
```

### `ocr llm test`

```text
ocr llm test
```

Определяет конечную точку LLM точно так же, как `ocr review`, отправляет один шаблонный запрос чата из [`internal/config/testconnection/task.json`](https://github.com/alibaba/open-code-review/blob/main/internal/config/testconnection/task.json) и выводит:

```
Источник: <использованная стратегия>
URL:      <URL конечной точки>
Модель:   <итоговая модель>
<ответ модели>
✓ Проверка подключения успешна
```

Ненулевой код завершения означает, что конечная точка настроена не полностью или запрос завершился ошибкой (сеть / аутентификация / модель). Сообщение ошибки укажет причину.

### `ocr llm providers`

```text
ocr llm providers
```

Выводит каждый встроенный LLM-провайдер в таблице из трёх столбцов:

```
Встроенные провайдеры:
  ИМЯ         ПРОТОКОЛ    БАЗОВЫЙ URL
  ---         --------    -----------
  anthropic   anthropic   https://api.anthropic.com
  …
```

После таблицы выводится подсказка о настройке провайдера интерактивно через `ocr config provider` или без интерактивного режима через `ocr config set provider <name>`.

## `ocr viewer`

```text
ocr viewer [flags]

Флаги:
  --addr <address>   адрес прослушивания (по умолчанию: localhost:5483)

Примеры:
  ocr viewer                     # запустить на порту по умолчанию
  ocr viewer --addr :3000        # привязать ко всем интерфейсам на порту 3000
```

Запускает встроенный HTTP-сервер, который читает `~/.opencodereview/sessions/...` и отображает прошлые сессии ревью в удобном для браузера интерфейсе. См. [Просмотр сессий](../viewer/).

## `ocr version`

```text
ocr version
ocr --version
ocr -V
```

Выводит версию, заданную при сборке, короткий Git-коммит (если есть), платформу (`<GOOS>/<GOARCH>`), дату сборки (если есть) и URL GitHub (`https://github.com/alibaba/open-code-review`).

## Советы и нюансы

- `--audience agent` **не** подразумевает `--format json`. Они управляют разными вещами: тихим UI и структурированными данными. Сочетайте их, если нужны оба результата.
- `--background` — один из наиболее важных флагов для качества ревью: всегда передавайте требования / описание PR при вызове из другого агента.
- Файл, чей diff сам по себе превышает 80 % от `MAX_TOKENS` (`58888` по умолчанию), отбрасывается до вызова LLM. Это записывается в журнал, но не завершает запуск ошибкой.
- Фаза плана **автоматически пропускается**, когда число изменённых строк файла меньше `PLAN_MODE_LINE_THRESHOLD` (`50`).

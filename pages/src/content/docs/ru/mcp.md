## Управление серверами и импорт

Менеджер работает в одном полноэкранном сеансе терминала. **CONFIGURED SERVERS** и **MANAGEMENT ACTIONS** показаны отдельно; **Tab** переключает разделы. Добавление, импорт, редактирование и права заменяют текущую страницу, а не появляются под ней. Отмена возвращает к выбранному пункту без сохранения. **PgUp/PgDn** прокручивают длинный предварительный просмотр. **Ctrl-C** завершает работу с любой страницы и восстанавливает прежний экран терминала. **Q** завершает работу только на страницах навигации, оставаясь обычной буквой в полях ввода.

`ocr mcp` открывает список серверов. Выберите сервер, затем его инструменты, подключение или права. **Esc** возвращает на предыдущий уровень, **Q** завершает работу. После действия остаётся выбранный сервер. Открытие списка не подключает серверы. Состояние конфигурации не означает доступность: результат discovery показан как последняя проверка в текущем сеансе, а не постоянное соединение.

**Tools** показывает настроенные инструменты без подключения. **Test connection** требует подтверждения запуска или соединения и получает только каталог. Новые инструменты не выбраны. Отображаются эффективные права, включая родительский deny, отключение и обнаруженное изменение определения. Отключение инструмента работает офлайн. Принятие нового определения требует повторного подключения и возвращает этому инструменту `ask`. При запуске review отпечатки проверяются снова.

**Import (JSON / TOML)** позволяет выбрать файл или вставить конфигурацию без отображения содержимого. **Ctrl-S** открывает предварительный просмотр, **Esc** отменяет. Поддерживаются Cursor JSON с `mcpServers` и Codex TOML с `mcp_servers`.

```bash
ocr mcp import [file] [--yes]
ocr mcp import ./mcp.json
ocr mcp import ./one-server.toml --yes
```

За один раз импортируется одно отключённое подключение без инструментов и разрешений. setup не запускается, сетевых обращений нет. Существующие имена не перезаписываются; в диалоге можно изменить имя. Лимиты: 1 MiB и 64 сервера. Неинтерактивный импорт требует одного сервера и `--yes`; `-` читает stdin.

Открытые значения env/header не копируются: вместо них сохраняются ссылки `${VARIABLE_NAME}` или `${OCR_MCP_HEADER_NAME}`. Предпросмотр показывает переменные, которые нужно задать перед подключением. Переменная header содержит полное значение, включая Bearer при необходимости. `bearer_token_env_var` преобразуется в ссылку с Bearer. Аргументы команды и URL сохраняются, секретные значения скрываются в предпросмотре; не помещайте туда учётные данные.

OAuth, рабочий каталог `cwd`, вспомогательные команды и неподдерживаемые поля отклоняются. После импорта выберите **Edit connection**, подтвердите discovery, выберите инструменты и сохраните. Независимая авторизация перед выполнением остаётся обязательной.

OpenCodeReview может использовать инструменты серверов **Model Context Protocol
(MCP)** во время `ocr review`. Команда `ocr scan` MCP не загружает.

Сервер MCP — это внешний код, а метаданные его инструментов недоверенные.
Поэтому простое добавление сервера не открывает модели все его инструменты. OCR
сначала обнаруживает каталог, а затем пользователь выбирает явный allowlist
инструментов и разрешение на выполнение.

## Два независимых рубежа безопасности

Каждый вызов MCP должен пройти два независимых рубежа:

1. **Видимость возможности.** MCP глобально и сервер должны быть включены,
   инструмент должен входить в allowlist `tools` этого сервера, а сохранённый
   fingerprint определения — совпадать с результатом discovery. Только тогда
   модель увидит инструмент.
2. **Авторизация выполнения.** Непосредственно перед `tools/call` OCR повторно
   проверяет сервер, инструмент, fingerprint, context и итоговое разрешение.
   `ask` открывает запрос в терминале; `allow` пропускает только этот запрос.

Пустой или отсутствующий `tools` означает **ноль инструментов**, а не все.
Ни `allow`, ни объявленные сервером annotation не расширяют allowlist. Отказ,
отмена, тайм-аут, EOF или невозможность интерактивного ввода означают, что
запрос `tools/call` не отправляется.

## Мастер подключения

Откройте manager в терминале:

```bash
ocr mcp
```

Или сразу запустите мастер добавления:

```bash
ocr mcp add docs
```

Мастер выполняет транзакцию из семи шагов:

1. выбор соединения `stdio` или `remote`;
2. ввод параметров без отображения сохранённых secret values;
3. показ точного локального executable и структуры аргументов (значения, похожие
   на credentials, маскируются) либо замаскированного
   remote endpoint и имён header;
4. подтверждение до запуска или подключения к серверу;
5. инициализация MCP и чтение всех страниц `tools/list` без вызова инструмента;
6. исходно не выбран ни один инструмент, пользователь отмечает нужные;
7. показ замаскированной сводки и однократная atomic-запись после финального
   подтверждения.

Стрелки выбирают пункт, **Space** отмечает инструмент, **Enter** продолжает,
**Ctrl-B** возвращает к редактированию, **Esc / Ctrl-C** отменяет без записи.
Вводить JSON не нужно: добавляйте аргументы по одному и указывайте имена
переменных окружения вместо токенов. Пункт **Save disabled (no connection)**
сохраняет отключённое соединение без подключения. При ошибке подключения можно
изменить настройки и повторить попытку. Выбранные инструменты начинают с `ask`.
После сохранения меню `ocr mcp permissions docs` позволяет явно выбрать `allow`;
родительский `deny` по-прежнему имеет приоритет.

Отказ от финального подтверждения или отмена завершают мастер без записи.
Сам запуск недоверенного локального процесса или подключение к remote
server может вызвать побочные эффекты на стороне сервера, даже если discovery
не вызывает бизнес-инструменты. Всегда проверяйте preview соединения.

### Локальный сервер stdio

```bash
ocr mcp add docs
# Выбор: stdio
# Executable: npx
# Аргументы: -y, затем настоящее имя MCP-пакета; пустая строка продолжает
# Имя переменной: DOCS_TOKEN; переменная-источник: DOCS_TOKEN
```

Дочерний процесс получает небольшой набор platform-переменных (`PATH`,
home/temp, locale) и только записи, явно указанные в `env`; полное окружение OCR
не наследуется. Новые значения мастера обязаны использовать ссылки `${ENV_NAME}`. Старые literal values
читаются для миграции, но помечены deprecated и маскируются во всех выводах.

До запуска OCR показывает executable и структуру аргументов, маскируя похожие на
credentials значения flags и URL query. В manager сервер
запускается только после подтверждения, а во время review — только если хотя бы
один инструмент потенциально видим.

### Удалённый сервер

```bash
ocr mcp add knowledge
# Выбор: remote
# URL: https://mcp.example.com/v1
# Имя header: Authorization; переменная-источник: MCP_TOKEN
# Необязательный префикс: Bearer с пробелом в конце
```

Для remote URL требуется HTTPS, кроме localhost/loopback. HTTP к другому host
требует явного `allow_insecure_http` и дополнительного подтверждения риска.
URL с userinfo или fragment и недопустимые headers отклоняются. Нельзя
переопределять transport-controlled и зарезервированные MCP protocol headers:
`Host`, `Content-Length`, MCP session/protocol headers, `Accept`, `Content-Type`.
Authentication headers, например `Authorization`, настраиваются, но всегда
маскируются в output.
Новые значения header в manager обязаны использовать ссылки `${ENV_NAME}`
(например, `Bearer ${MCP_TOKEN}`); literal credentials отклоняются.

Настроенные headers отправляются только исходному same-origin адресу.
Cross-origin redirects и downgrade с HTTPS на HTTP отклоняются. CLI и JSON
status показывают только замаскированный endpoint и имена header, никогда не
показывая header values или значения URL query.

## Discovery и выбор инструментов

Посмотрите каталог, не меняя конфигурацию:

```bash
ocr mcp discover docs
ocr mcp discover docs --json
```

Discovery выполняет только инициализацию MCP и все страницы `tools/list`. Он не
вызывает `tools/call`, не регистрирует инструменты для модели и не сохраняет
каталог. TTY запрашивает подтверждение; вне интерактивного терминала обязателен
`--yes`.

Выберите инструменты в интерактивном editor или по точным именам:

```bash
ocr mcp tools docs
ocr mcp tools docs --enable search_docs --enable get_page --yes
ocr mcp tools docs --disable get_page --yes
```

Новое включение получает разрешение `ask`. Отключение удаляет также разрешение
и fingerprint. Ограничения discovery: 64 страницы, 512 инструментов, 4 MiB на
каталог, 8 KiB на описание, 256 KiB на input schema. Некорректные, повторные и
слишком большие каталоги обрабатываются fail closed.

Описания, schema, title, icons и annotations — недоверенные server metadata.
OCR очищает и ограничивает их. Например, `readOnlyHint` может отображаться лишь
как непроверенная подсказка сервера и никогда не даёт разрешение автоматически.

## Разрешения

| Значение | Смысл |
|---|---|
| `deny` | Жёсткий запрет. `deny` на global/server нельзя переопределить ниже. |
| `ask` | Показывать подходящий инструмент только в интерактивном review и спрашивать перед каждым uncached вызовом. |
| `allow` | Пропустить prompt для подходящего инструмента; само по себе не включает инструмент. |
| `inherit` | Только server/tool: унаследовать решение более широкого scope. |

Если выше нет `deny`, побеждает наиболее конкретное не-`inherit` значение:

```text
tool > server > global (по умолчанию: ask)
```

Постоянный `allow` записывается только командой permissions и лишь для
включённого инструмента с актуальным discovery fingerprint:

```bash
# Global policy и тайм-аут подтверждения
ocr mcp permissions
ocr mcp permissions --default ask --timeout 60 --yes

# Переопределения сервера и точного инструмента
ocr mcp permissions docs
ocr mcp permissions docs --default inherit \
  --tool search_docs=ask --tool get_page=allow --yes
```

`approval_timeout_seconds` настраивается глобально, по умолчанию равен 60
секундам и принимает значения 1–600:

```bash
ocr config set mcp.approval_timeout_seconds 120
```

Изменение применяется со следующего запуска `ocr review`.

### Подтверждение во время выполнения

Prompt для `ask` показывает сервер, исходное имя инструмента, qualified model
alias, недоверенное описание, префикс fingerprint и ограниченный,
замаскированный preview аргументов. Варианты ответа:

- **Allow once**
- **Allow this review**
- **Deny once** (по умолчанию)
- **Deny this review**

Решение уровня review использует точную identity server/tool, разделяется между
параллельными группами этого review и исчезает при завершении процесса.
Runtime approval никогда не изменяет конфигурацию.

## Identity инструмента и изменение определения

Модель получает qualified alias вместо исходного имени MCP:

```text
mcp__<server-slug>__<tool-slug>__<16-hex>
```

Hash связывает точный, чувствительный к регистру server config key и remote
tool name. OCR хранит immutable mapping alias-to-tool и не восстанавливает
identity разбором alias. Любой конфликт со встроенным именем, другим MCP alias
или существующим registry останавливает регистрацию всех MCP в текущем review,
не допуская частичной видимости. Встроенные инструменты остаются доступны.

При сохранении проверяются параллельные изменения. Если другое окно сохранило
настройки, пока форма была открыта, устаревший черновик отклоняется; откройте
настройки заново. Приватный файл `config.json.lock` координирует запись OCR и не
содержит секретов. Не удаляйте его во время работы OCR. Старые версии и ручные
редакторы не используют эту блокировку; избегайте одновременного редактирования.

Для каждого выбранного инструмента хранится SHA-256 fingerprint соединения,
имени, очищенного описания и canonical input schema. Изменённый или отсутствующий
fingerprint даёт статус `needs-review` и скрывает инструмент до принятия нового
определения через `ocr mcp tools` или `ocr mcp edit`. Annotations и resolved
secret values в fingerprint не входят.

## CI и неинтерактивный режим

OCR считает запуск интерактивным, только если stdin и stderr — terminal,
`TERM` не равен `dumb`, а распространённые CI variables не истинны. Значения
`0`, `false`, `no`, `off` считаются false. GitHub Actions, GitLab CI, Azure
Pipelines, Buildkite, Jenkins и общий `CI` работают fail closed.

- Инструменты `ask` скрыты и не могут выполняться.
- Только явно включённый инструмент `allow` с совпадающим fingerprint может
  выполняться, но он всё равно проходит независимый authorizer непосредственно
  перед MCP call.
- `ocr mcp` без subcommand выводит только замаскированный status/help, не
  подключается и не пишет конфигурацию.
- Команды, способные подключаться или менять состояние, требуют всех flags и
  явного `--yes`.

Применяйте постоянный `allow` в CI минимально: ограничьте credentials сервером
и инструментом и закрепите или иначе проверьте пакет запускаемого сервера.

## Справочник команд управления

```text
ocr mcp
ocr mcp add [name]
ocr mcp list [--json]
ocr mcp show <name> [--json]
ocr mcp edit <name>
ocr mcp discover <name> [--json] [--yes]
ocr mcp tools <name> [--enable TOOL ...] [--disable TOOL ...] [--yes]
ocr mcp permissions [name]
ocr mcp enable <name> [--yes]
ocr mcp disable <name> [--yes]
ocr mcp remove <name> [--yes]
```

`list` и `show` не подключаются к серверу. `remove` в терминале по умолчанию
выбирает No, а вне терминала требует `--yes`. `enable` меняет только switch
сервера и не добавляет инструменты в allowlist.

## Конфигурация и миграция

Manager записывает versioned policy в `~/.opencodereview/config.json`:

Глобальные ключи: `mcp.version`, `mcp.enabled`, `mcp.default_permission` и
`mcp.approval_timeout_seconds`; именованные подключения находятся в `mcp_servers`.

```json
{
  "mcp": {
    "version": 1,
    "enabled": true,
    "default_permission": "ask",
    "approval_timeout_seconds": 60
  },
  "mcp_servers": {
    "docs": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@acme/docs-mcp-server"],
      "env": ["DOCS_TOKEN=${DOCS_TOKEN}"],
      "enabled": true,
      "default_permission": "inherit",
      "tools": ["search_docs"],
      "tool_permissions": {"search_docs": "ask"},
      "tool_definition_sha256": {"search_docs": "<64-lowercase-hex>"}
    }
  }
}
```

Обычный review читает legacy config, но не переписывает его автоматически.
Старый непустой `tools` без fingerprint ограничен интерактивным `ask` и не
может автоматически выполняться в CI. Старый пустой или отсутствующий `tools`
ничего не открывает. Первая успешная запись через manager сохраняет version 1
и принятые fingerprints.

Старое поле `setup` больше не выполняется в `ocr review`. Когда manager сохраняет
такой сервер, поле удаляется с предложением установить или собрать сервер
вручную. Старые версии OCR не должны редактировать мигрированный config: они не
знают новых security fields и могут удалить их при перезаписи.

Запись идёт через временный файл mode `0600` в том же каталоге, flush и atomic
replace. Отмена wizard или ошибка discovery сохраняют исходный файл без изменений.

Права `0600` действуют в Unix-подобных системах. Windows использует ACL,
унаследованные от каталога, а не биты прав Unix. Ограничьте доступ к каталогу
конфигурации своей учётной записью.

## Устранение неполадок

- **`needs-review`**: выполните `ocr mcp tools <name>`, примите текущее определение
  и выберите разрешение.
- **В CI нет MCP tools**: `ask` намеренно скрыт. При необходимости используйте
  текущий fingerprint и минимальный постоянный `allow`.
- **Discovery не работает**: проверьте executable/аргументы или замаскированный
  origin, нужные environment variables, TLS и совместимость MCP.
- **Слишком большой результат**: aggregate больше 1 MiB отклоняется; сузьте query.
- **Ошибка сервера**: MCP `isError` считается не успешной telemetry, а ошибкой выполнения.
- **Конфликт имён**: измените server config key или remote tool name; first-wins
  больше не используется.

## Подключение в терминале

`ocr mcp add` предлагает пошаговый ввод и выбор инструментов клавишей `Space`. `Enter` продолжает, `Ctrl-B` возвращает назад, `Esc` отменяет. Права и тайм-аут (по умолчанию 60 секунд, 1–600) задаются через `ocr mcp permissions`. Команды настройки и review используют `~/.opencodereview/config.json`. Для изолированного теста задайте `HOME` (и `USERPROFILE` в Windows) только для процесса OCR, указав отдельный тестовый каталог. Только отзыв через `ocr mcp tools docs --disable write` работает офлайн, без подключения и без `--yes`. Включение требует discovery и явного согласия на подключение.

## История и raw-логи

Когда в review доступны инструменты MCP, запись raw отключается даже при `OCR_RAW_LOGGING=1`. В истории аргументы чувствительных вызовов маскируются; native payload и сопутствующий текст рассуждений не сохраняются, поскольку могут повторять аргументы. Исходные данные для продолжения диалога модели остаются неизменными. Для дочерних процессов используется тайм-аут завершения SDK; соединения закрываются параллельно с ограничением ожидания.

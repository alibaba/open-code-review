OCR может работать как **клиент Model Context Protocol (MCP)**. Укажите один
или несколько внешних серверов MCP, и предоставляемые ими инструменты станут
доступны агенту ревью наряду со [встроенными инструментами](../tools/), такими
как `file_read` и `code_search`.

## Когда использовать MCP

Подключайте сервер MCP, если ревьюеру полезен контекст за пределами diff:

- **Поиск задач / тикетов** — агент может получить связанную задачу Jira или
  GitHub и проверить, соответствует ли изменение заявленным требованиям.
- **Документация / база знаний** — загрузить внутреннюю документацию API или
  стандарты программирования, чтобы комментарии ссылались на действующие
  правила организации.
- **Пользовательский анализ** — предоставить линтер, валидатор схем или средство
  проверки зависимостей как инструмент, который ревьюер может вызвать по мере
  необходимости.

Если требуется только читать репозиторий, встроенные инструменты уже
обеспечивают это. MCP предназначен для доступа за пределы рабочей копии.

## Конфигурация

#### Добавление локального сервера MCP

Команда `ocr config set` записывает эти поля неинтерактивно. Поля-массивы
(`args`, `env`, `tools`) принимают строку с JSON-массивом:

```bash
# Minimal: just a command
ocr config set mcp_servers.docs.command npx

# Arguments
ocr config set mcp_servers.docs.args '["-y", "@acme/docs-mcp-server"]'

# Restrict which tools are exposed to the reviewer
ocr config set mcp_servers.docs.tools '["search_docs", "get_page"]'

# A setup command to run before the server starts
ocr config set mcp_servers.docs.setup "npm install -g @acme/docs-mcp-server"

# Environment variables (KEY=VALUE entries)
ocr config set mcp_servers.docs.env '["DOCS_TOKEN=secret", "DOCS_REGION=eu"]'
```

#### Добавление удалённого сервера MCP

Для серверов с поддержкой **Streamable HTTP** установите `type` в `remote` и
укажите `url` вместо локальной команды. Одного `url` недостаточно: тип по
умолчанию — `stdio`.

Используйте новое имя сервера, чтобы эти команды не перезаписали существующее
подключение:

```bash
ocr config set mcp_servers.search.type remote
ocr config set mcp_servers.search.url https://mcp.example.com/mcp
ocr config set mcp_servers.search.tools '["search", "fetch"]'
```

Эти команды сохраняют подключение в вашей пользовательской конфигурации. При
следующем ревью OCR подключится и предоставит агенту `search` и `fetch` наряду
со встроенными инструментами. Список разрешённых инструментов оставляет за
пределами ревью всё остальное, что может предлагать сервер. Другие настроенные
серверы и параметры ревью не меняются.

После настройки агент вызывает эти инструменты во время ревью, не спрашивая
подтверждения перед каждым вызовом. Аргументы инструментов — поисковые запросы,
запрашиваемые URL и любой контекст, который добавляет агент, — покидают вашу
машину и попадают к тому, кто обслуживает эту конечную точку. Поскольку это
пользовательская конфигурация, она действует во всех репозиториях: включайте её
только там, где внешние запросы допустимы, и не передавайте в запросах секреты,
закрытый код или внутренние URL. Прежде чем подключать сторонний сервис,
ознакомьтесь с его политикой конфиденциальности и условиями использования.

#### Удаление сервера MCP

Удалите сервер с помощью `unset`:

```bash
ocr config unset mcp_servers.docs
```

Серверы MCP находятся в ключе `mcp_servers` пользовательского файла
конфигурации (`~/.opencodereview/config.json`).

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `type` | строка | | `stdio` (по умолчанию) для локального подпроцесса или `remote` для Streamable HTTP. |
| `command` | строка | Для `stdio` | Исполняемый файл, запускающий сервер MCP (например, `npx`, `uvx` или абсолютный путь). |
| `args` | массив строк | | Аргументы, передаваемые `command` (только для `stdio`). |
| `url` | строка | Для `remote` | Конечная точка MCP по HTTP или HTTPS. |
| `headers` | объект | | Имена HTTP-заголовков и их строковые значения (только для `remote`). Значения раскрывают `$VAR` или `${VAR}` из окружения OCR в момент подключения; значение, раскрывшееся в пустую строку, **обрывает подключение с ошибкой**, а не отправляется пустым и не отбрасывается. Опустите для анонимного доступа. |
| `tools` | массив строк | | Список разрешённых имён инструментов для регистрации. Пустое значение регистрирует все инструменты сервера. |
| `setup` | строка | | Команда оболочки, однократно выполняемая перед запуском сервера (только для `stdio`, например установка зависимостей). Выполняется в корне репозитория с тайм-аутом 5 минут. |
| `env` | массив строк | | Дополнительные переменные окружения подпроцесса в формате `KEY=VALUE` (только для `stdio`). |

Для удалённых серверов, требующих аутентификации, настраивайте `headers` по
инструкции соответствующего сервера. Если передаваемый в `ocr config set` JSON
содержит ссылки на переменные окружения, заключайте его в одинарные кавычки,
чтобы оболочка не раскрыла их до того, как OCR сохранит конфигурацию. Серверам с
анонимным доступом `headers` не нужны вовсе.

## Фильтрация инструментов

По умолчанию регистрируется каждый инструмент, объявленный сервером. Если
сервер предоставляет больше инструментов, чем нужно ревьюеру, задайте в
`tools` список разрешённых: меньшее число точных инструментов помогает агенту
сосредоточиться и сокращает расход токенов. Имена из списка, которых на самом
деле нет на сервере, пропускаются с предупреждением, поэтому опечатка выводится
в stderr, а не остаётся незаметной.

## Конфликты имён

Инструменты MCP используют одно пространство имён со встроенными инструментами.
Если сервер объявляет инструмент, имя которого совпадает со
**встроенным/зарезервированным** (`file_read`, `code_search`, `task_done` и т. д.)
или с инструментом, уже зарегистрированным другим сервером MCP, OCR
**пропускает** его и записывает предупреждение. Побеждает первая регистрация;
давайте инструментам разных серверов уникальные имена, чтобы они не терялись.

## Команда `setup`

`setup` выполняется один раз из корня репозитория перед запуском подпроцесса
сервера. Используйте её, чтобы установить или собрать сервер по необходимости:

```json
"setup": "npm install -g @acme/docs-mcp-server"
```

Для команды установлен **тайм-аут 5 минут**. Если она завершается с ненулевым
кодом, OCR записывает команду, рабочий каталог и вывод, затем пропускает этот
сервер и продолжает ревью.

## Устранение неполадок

Вся диагностика MCP выводится в **stderr** с префиксом `[ocr]`, поэтому она
никогда не загрязняет вывод `--format json` в stdout:

- `Running setup for MCP server "x": …` — выполняется команда настройки.
- `failed to start MCP server "x": …` — подпроцесс не подключился за
  30-секундный тайм-аут инициализации или `command` отсутствует в `PATH`.
- `remote MCP server "x" has no URL configured, skipping` — `type` равен
  `remote`, но `url` не задан; обратная сторона случая, когда задан `url` без
  `type`.
- `failed to connect to remote MCP server "x": …` — конечная точка не
  подключилась и не выдала список инструментов за 30-секундный тайм-аут
  инициализации. Проверьте URL, сетевой доступ и требуемые заголовки.
- `MCP server "x" header "h" expanded to empty value` — переменная `$VAR` из
  `headers` не задана в окружении OCR. Это обрывает подключение, а не
  трактуется как отсутствующий заголовок.
- `remote MCP server "x" returned HTTP 401 Unauthorized` — проверьте токен или
  настройку заголовков.
- `remote MCP server "x" returned HTTP 403 Forbidden` — учётные данные дошли до
  сервера, но не дают нужных прав.
- `tool "y" conflicts with built-in tool, skipping` — переименуйте инструмент
  сервера или удалите его из `tools`.
- `allowed tool "y" not found in server's tool list` — имя в `tools` не
  соответствует ни одному инструменту сервера; проверьте написание.

Сервер, который не удалось запустить или к которому не удалось подключиться,
пропускается; ревью продолжается без его инструментов.

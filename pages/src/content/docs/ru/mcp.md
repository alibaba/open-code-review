OCR может выступать **клиентом Model Context Protocol (MCP)**. Укажите один или несколько внешних серверов MCP, и предоставляемые ими инструменты станут доступны агенту ревью вместе со [встроенными инструментами](../tools/), такими как `file_read` и `code_search`.

## Когда использовать

Используйте сервер MCP, когда ревьюеру нужен контекст за пределами diff:

- **Поиск задач / тикетов** — агент может получить связанную задачу Jira / GitHub и проверить, соответствует ли изменение заявленному требованию.
- **Документация / база знаний** — можно получать внутреннюю документацию по API или стандарты кодирования, чтобы комментарии ссылались на реальные правила команды.
- **Пользовательский анализ** — предоставьте линтер, валидатор схемы или средство проверки зависимостей в качестве инструмента, который ревьюер сможет вызывать по запросу.

Если нужно только прочитать репозиторий, встроенные инструменты уже покрывают эту задачу — MCP нужен для доступа за пределы рабочей копии.

## Конфигурация

#### Добавление сервера MCP

Команда `ocr config set` записывает эти поля в неинтерактивном режиме. Поля-массивы (`args`, `env`, `tools`) принимают строку с JSON-массивом:

```bash
# Минимальный вариант: только команда
ocr config set mcp_servers.docs.command npx

# Аргументы
ocr config set mcp_servers.docs.args '["-y", "@acme/docs-mcp-server"]'

# Ограничить набор инструментов, доступных ревьюеру
ocr config set mcp_servers.docs.tools '["search_docs", "get_page"]'

# Команда подготовки, выполняемая перед запуском сервера
ocr config set mcp_servers.docs.setup "npm install -g @acme/docs-mcp-server"

# Переменные окружения (записи KEY=VALUE)
ocr config set mcp_servers.docs.env '["DOCS_TOKEN=secret", "DOCS_REGION=eu"]'
```

#### Удаление сервера MCP

Удалите сервер с помощью `unset`:

```bash
ocr config unset mcp_servers.docs
```

Серверы MCP находятся в ключе `mcp_servers` пользовательского файла конфигурации (`~/.opencodereview/config.json`).

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `command` | строка | ✓ | Исполняемый файл, запускающий сервер MCP (например, `npx`, `uvx`, абсолютный путь). |
| `args` | массив строк | | Аргументы, передаваемые в `command`. |
| `tools` | массив строк | | Разрешённый список имён регистрируемых инструментов. Пустое значение = зарегистрировать все инструменты, предлагаемые сервером. |
| `setup` | строка | | Команда оболочки, выполняемая один раз перед запуском сервера (например, для установки зависимостей). Выполняется в корне репозитория с 5-минутным тайм-аутом. |
| `env` | массив строк | | Дополнительные переменные окружения в формате `KEY=VALUE`. |

## Фильтрация инструментов

По умолчанию регистрируется каждый инструмент, который объявляет сервер. Укажите в `tools` разрешённый список, если сервер предоставляет больше инструментов, чем нужно ревьюеру: меньшее число более точных инструментов помогает агенту сосредоточиться и снижает расход токенов. Имена из списка, которые сервер на самом деле не предлагает, пропускаются с предупреждением; поэтому опечатка выводится в stderr, а не остаётся незамеченной.

## Конфликты имён

Имена инструментов MCP используют общее пространство имён со встроенными инструментами. Если сервер объявляет инструмент, имя которого конфликтует со **встроенным/зарезервированным** инструментом (`file_read`, `code_search`, `task_done`, …) либо с инструментом, уже зарегистрированным другим сервером MCP, OCR **пропускает** его и записывает предупреждение в журнал. Выигрывает первая регистрация; давайте серверам разные имена инструментов, чтобы не потерять их таким образом.

## Команда `setup`

`setup` выполняется один раз из корня репозитория до запуска дочернего процесса сервера. Используйте её для установки или сборки сервера по требованию:

```json
"setup": "npm install -g @acme/docs-mcp-server"
```

Для неё действует **5-минутный тайм-аут**. Если команда завершается с ненулевым кодом, OCR записывает команду, рабочий каталог и вывод в журнал, затем пропускает этот сервер и продолжает ревью.

## Устранение неполадок

Все диагностические сообщения MCP выводятся в **stderr** с префиксом `[ocr]`, поэтому они не загрязняют вывод `--format json` в stdout:

- `Running setup for MCP server "x": …` — выполняется команда `setup`.
- `failed to start MCP server "x": …` — дочерний процесс не подключился в пределах 30-секундного тайм-аута инициализации либо `command` отсутствует в `PATH`.
- `tool "y" conflicts with built-in tool, skipping` — переименуйте инструмент сервера или исключите его из `tools`.
- `allowed tool "y" not found in server's tool list` — имя в `tools` не соответствует ни одному инструменту сервера; проверьте написание.

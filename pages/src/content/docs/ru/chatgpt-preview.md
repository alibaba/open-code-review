---
title: Предварительная версия входа через ChatGPT
---

OpenCodeReview может использовать доступный лимит тарифа ChatGPT через публичный API Responses от OpenAI. Эта необязательная функция предварительной версии доступна в CLI с открытым исходным кодом. OpenCodeReview не взимает отдельную плату за подписку. Доступность зависит от аккаунта, рабочего пространства, региона и модели и определяется OpenAI.

Провайдер `chatgpt` использует документированный процесс Sign in with ChatGPT. `ocr auth login`, `status` и `logout` по умолчанию используют Sign in with ChatGPT. Явный параметр `--provider chatgpt` также поддерживается.

## Вход и выбор модели

```bash
ocr auth login --provider chatgpt
ocr auth status --provider chatgpt
ocr llm models
ocr config set provider chatgpt
ocr config set providers.chatgpt.model gpt-6-luna
ocr config set providers.chatgpt.extra_body '{"reasoning":{"effort":"low"}}'
ocr llm test
```

Регистрация OAuth запрашивает полный набор областей OpenID Connect и OpenAI: `openid` (проверка личности), `profile` и `email` (данные аккаунта), `offline_access` (обновление токена без присутствия пользователя), `resource.invoke` (вызов ресурса) и `chatgpt.tokens.use.direct` (прямое использование лимита тарифа ChatGPT). При первой регистрации отправляется `agent_name_hint=OpenCodeReview`. Права для коннекторов не запрашиваются, регистрация клиента Codex CLI не используется повторно. Запрашиваются только области, нужные для документированного процесса, без произвольных дополнительных прав.

При первом входе OpenAI выдает регистрацию клиента, которую приложение сохраняет для этого аккаунта. При первой регистрации отправляется фактическое имя приложения, одинаковое для всех установок, а при повторном входе подсказка опускается. При каждом входе приложение отправляет постоянный непрозрачный `ext_agent_host_id` для этой локальной установки. Одна установка сохраняет один и тот же идентификатор хоста.

Для каждой авторизации создаются новые state, nonce и значения PKCE. Состояние callback проверяется до обмена кода. Подпись ID-токена проверяется по RSA JWKS издателя; до принятия личности и выданных областей проверяются issuer, audience, subject, срок действия и nonce.

Список моделей показывает предложения и отображаемые имена, доступные выбранному аккаунту, в порядке сервера. Если модель не задана, провайдер выбирает первую видимую модель. Явно заданный идентификатор модели или параметр `--model` отправляется в OpenAI без изменений, даже если его нет в списке. Доступность модели для аккаунта определяет OpenAI. В этот провайдер не встроены ограничения или псевдонимы моделей.

Параметр reasoning effort в `extra_body` относится к API. Отдельный флаг review `--effort` задаёт число раундов проверки и бюджет инструментов OpenCodeReview.

Вход открывает системный браузер и слушает только `127.0.0.1`. Параметр `--no-browser` выводит одноразовый локальный URL. CLI не печатает URL авторизации с сохраненной подсказкой ID-токена. В этой предварительной версии вход по коду устройства не поддерживается.

Если вход выполнен без разрешения на использование тарифа ChatGPT, OpenCodeReview сохраняет личность аккаунта и сообщает, что использование тарифа выключено. Чтобы запросить страницу согласия для сохраненной регистрации, выполните:

```bash
ocr auth login --provider chatgpt --enable-plan
# Для другой сохраненной регистрации:
ocr auth login --provider chatgpt --enable-plan --account <saved-client-id>
```

Это явное действие отправляет `prompt=consent`, полный набор запрашиваемых областей и ресурс, а также сохраненные идентификаторы клиента и хоста. Параметр нельзя использовать вместе с `--new-account`. Обычный повторный вход не требует согласия заново. Запросы остаются выключенными, пока выданное разрешение не допускает использование тарифа. Можно настроить провайдер с API-ключом; OpenCodeReview не переключает способ оплаты автоматически.

## Аккаунты и выход

```bash
ocr auth login --provider chatgpt --new-account
ocr auth status --provider chatgpt
ocr auth select <saved-client-id> --provider chatgpt
ocr auth login --provider chatgpt --account <saved-client-id>
ocr auth logout --provider chatgpt --account <saved-client-id>
```

Каждый выданный идентификатор клиента связан с проверенными issuer и subject, поэтому регистрации различаются даже при одинаковом адресе электронной почты. Повторный вход использует тот же идентификатор клиента. После ошибки `invalid_grant` при обмене кода процесс авторизации однократно начинается заново с идентификатором клиента из callback и новыми state, nonce и PKCE. Ожидающая регистрация не активируется до проверки подписанной личности. При повторной ошибке вход прекращается, прежние учетные данные сохраняются.

База учетных данных находится в `~/.opencodereview/auth/chatgpt/accounts.json`. Отдельный `host.json` хранит постоянный идентификатор установки. Файлы учетных данных заменяются атомарно.

В Unix файлы учетных данных имеют права `0600`, доступные только владельцу, а каталог хранилища имеет права `0700`. В Windows доступ зависит от ACL, унаследованных от локального профиля пользователя; OpenCodeReview не устанавливает и не проверяет DACL. Функция Go [`os.Chmod`](https://pkg.go.dev/os#Chmod) в Windows изменяет только атрибут «только чтение». Используйте профиль пользователя, ACL которого ограничивают доступ вашей учетной записью, проверяйте права перед входом и избегайте общих или широко доступных мест хранения. Нахождение каталога внутри профиля пользователя само по себе не гарантирует закрытый доступ.

Изменения хранилища и ротация refresh-токена используют блокировку ОС, но браузерная авторизация выполняется вне блокировки, чтобы другие аккаунты оставались доступны. При завершении хранилище перечитывается и проверяется версия регистрации. Выход, обновление токена или другой завершенный вход для этой регистрации делают ожидающий результат недействительным. Изменения других аккаунтов сохраняются. Access-токены обновляются до истечения срока с помощью ротируемых refresh-токенов.

При выходе предпринимается попытка отозвать обновляемую сессию, access-, refresh- и ID-токены удаляются, а регистрация аккаунта и идентификатор хоста сохраняются. После выхода при следующем входе `id_token_hint` не отправляется. Если удаленный отзыв подтвердить нельзя, CLI сообщает об удалении локальных токенов и предлагает отключить приложение в настройках ChatGPT.

## Передача запросов и лимиты

Этот провайдер отправляет запросы только на `https://api.openai.com/v1/responses`. Переопределение конечной точки, протокола и учетных данных отклоняется. Используется потоковая передача с `store: false`, отправляется полная история, локальные функции группируются в пространстве имен `ocr`, а идентификаторы вызовов и зашифрованное reasoning сохраняются для следующих ходов. Успехом считается только `response.completed`. При ошибке, неполном или прерванном потоке запрос прекращается, включая ошибку лимита после начала вывода.

Поля запросов предварительной версии ограничены поддерживаемым OpenAI набором. `extra_body` принимает `reasoning`, `text` и `prompt_cache_key`; менять модель, историю, инструменты, режим потока или политику хранения нельзя. Ответ сохраняет исходные данные об использовании провайдера. Существующая необязательная запись исходного потока проверки не включает заголовки учетных данных.

**Использование тарифа ChatGPT:** подходящие запросы используют тариф выбранного аккаунта. [Управление использованием в настройках ChatGPT](https://chatgpt.com/settings/usage). Ошибка лимита может относиться ко всему тарифу или отдельному приложению; CLI не пытается определить время сброса.

Текущие требования описаны в [обзоре SIWC для открытого исходного кода](https://developers.openai.com/siwc/token-sharing-open-source), [контракте входа](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) и [ограничениях предварительной версии](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) OpenAI.

Команды `ocr auth` и `ocr llm models` описаны в [справочнике CLI](../cli-reference/), а настройки провайдера описаны в [руководстве по конфигурации](../configuration/).

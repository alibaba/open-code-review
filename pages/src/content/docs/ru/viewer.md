`ocr viewer` — небольшой встроенный HTTP-сервер, отображающий прошлые сессии ревью в UI, удобном для браузера. Внешние зависимости не нужны: сессии читаются непосредственно из файлов JSONL, которые OCR записывает на диск во время каждого ревью.

## Запуск

```bash
ocr viewer                  # привязка к localhost:5483
ocr viewer --addr :3000     # привязка ко всем интерфейсам на порту 3000
ocr viewer --addr 0.0.0.0:8080   # привязка ко всем интерфейсам
```

Адрес по умолчанию — `localhost:5483`. Сервер работает на переднем плане; чтобы остановить его, нажмите `Ctrl+C`. При каждом запросе сессии лениво сканируются из `~/.opencodereview/sessions/`, поэтому ревью, запущенное в другом терминале, появится сразу после создания его JSONL-файла.

> **Защита от DNS-rebinding.** Просмотр сессий проверяет заголовок `Host` по списку разрешённых адресов обратной петли (`localhost`, `127.0.0.1`, `::1`). Конкретный хост привязки (например, `--addr 192.168.1.10:5483`) добавляется автоматически, но привязки с подстановочным адресом (`:3000`, `0.0.0.0`, `::`) — нет. Поэтому при обращении к UI с IP-адреса LAN или по имени хоста возвращается `forbidden host`. Чтобы открыть привязку с подстановочным адресом, задайте в `OCR_VIEWER_ALLOWED_HOSTS` список разрешённых имён хостов через запятую (например, `OCR_VIEWER_ALLOWED_HOSTS=box.local,192.168.1.10`).

## Три страницы

В просмотре сессий есть три URL:

| URL | Отображаемая информация |
|---|---|
| `/` | Список всех репозиториев с сохранёнными на диске сессиями. |
| `/r/{repo}` | Список сессий одного репозитория, начиная с новых. |
| `/r/{repo}/{sessionID}` | Полные сведения об одной сессии. |

`{repo}` — строка с кодированным путём (разделители `/` и `\` заменены на `-`, двоеточия — на `_`; используется то же кодирование, что и для имён каталогов на диске). Обычно вводить её не нужно — просто переходите по ссылкам.

### `/` — список репозиториев

Для каждого репозитория хотя бы с одной сессией отображаются путь репозитория, общее число сессий и отметка времени последней активности.

### `/r/{repo}` — список сессий репозитория

Для каждой сессии отображаются: ID (UUID), имя ветки (когда OCR смог его определить), режим ревью, модель, число файлов, длительность и время начала.

### `/r/{repo}/{sessionID}` — сведения о сессии

Страница сведений — наиболее важная. Она показывает:

1. **Заголовок** — диапазон diff, модель, ветку, общее число токенов, длительность запуска.
2. **Группу файлов** — по одному блоку на каждый файл, прошедший ревью. Внутри каждого файла пять дорожек «типов задач»:

| Тип задачи | Когда отображается |
|---|---|
| `plan_task` | Выполнялась фаза планирования (файл ≥ `PLAN_MODE_LINE_THRESHOLD`). |
| `main_task` | Для каждого файла. Основной цикл ревью. |
| `review_filter_task` | Для этого файла выполнялся проход фильтрации комментариев после ревью. |
| `memory_compression_task` | Активная зона и зона сжатия превысили бюджет 60 % / 80 %. |
| `re_location_task` | Не удалось привязать `code_comment`, поэтому выполнялось резервное повторное определение местоположения. |

Каждая дорожка — это горизонтальная полоса из **карточек задач**: по одной на каждый раунд обмена с LLM. Карточки окрашены по типу задачи, поэтому сразу видно, какие фазы преобладали в запуске.

## Что содержится в карточке задачи

Нажмите на карточку задачи, чтобы развернуть её. В каждой карточке есть:

- **строка заголовка** — номер запроса, бейдж модели, бейдж токенов (`P:` — входные / `C:` — выходные, а также `CR:` / `CW:` — чтение/запись кэша, если есть), бейдж длительности и бейдж ошибки, если раунд завершился с ошибкой;
- **Ответ** — исходный ответ ассистента, включая все блоки рассуждений / `thinking`;
- **Вызовы инструментов** — каждый вызов инструмента с аргументами и возвращённым результатом (сворачиваемый).

Полный список сообщений, отправленных модели, и определения инструментов в области видимости **не** отображаются в UI карточки. Если они нужны, просмотрите JSONL-транскрипт напрямую (поле `messages` в каждой записи `llm_request`).

## Сценарии использования

Просмотр сессий рассчитан на три рабочих процесса:

### «Почему модель сказала это?»

Откройте комментарий в выводе терминала, найдите файл в просмотре сессий и просмотрите его дорожку `main_task`. Карточка, чьи **вызовы инструментов** включают нужный `code_comment`, — это раунд, создавший комментарий. В разделе «Ответ» карточки показаны рассуждения модели; чтобы увидеть точный запрос и контекст, отправленные модели, откройте запись `llm_request` для этого номера запроса в JSONL-транскрипте (её поле `messages`).

### «Почему для этого файла нет комментариев?»

Файл **без комментариев** означает успешное ревью, только если модель *намеренно* вызвала `task_done`. Если дорожка показывает вызовы инструментов, но без `code_comment`, это намеренное чистое ревью. Если дорожка заканчивается карточкой ошибки, это сбой, замаскированный под отсутствие результата — покажите его как предупреждение.

### «Что сохранило / отбросило сжатие?»

Дорожка `memory_compression_task` показывает каждый раунд сжатия. Внутри в области «Ответ» находится итоговое резюме; отрисованный XML зоны сжатия, поданный на вход, находится в поле `messages` записи `llm_request` этого раунда в JSONL-транскрипте. Это полезно при отладке жалобы «модель забыла ранний контекст»: можно увидеть, отбросило ли сжатие важную деталь.

## Хранение на диске

Просмотр сессий читает данные из:

```
~/.opencodereview/sessions/
└── <path-encoded-repo-path>/
    └── <session-id>.jsonl
```

Каждая строка в JSONL-файле — одно событие:

```json
{"type": "llm_request", "filePath": "src/foo.go", "taskType": "main_task", "request_no": 1, "messages": [{"role": "user", "content": "Review this diff…"}], "timestamp": "2026-06-02T10:15:23Z"}
{"type": "llm_response", "filePath": "src/foo.go", "taskType": "main_task", "model": "claude-sonnet-4-6", "content": "Found 2 issues…", "duration_ms": 8421, "usage": {"prompt_tokens": 12450, "completion_tokens": 320}}
{"type": "tool_call", "filePath": "src/foo.go", "tool_name": "file_read", "arguments": "{\"file_path\":\"src/foo.go\",\"start_line\":1,\"end_line\":50}", "result": "File: src/foo.go (Total lines: 220)\nIS_TRUNCATED: false\nLINE_RANGE: 1-50\n1|package foo…", "ok": true, "duration_ms": 14}
```

Строки только добавляются: неполный JSONL означает, что сессия была прервана во время выполнения, и просмотр сессий отображает то, что доступно.

Чтобы освободить место на диске, удаляйте файлы сессий целиком; просмотр сессий пересоздаст индекс при следующем запросе.

## Конфиденциальность

JSONL-транскрипты содержат **всё**, что отправлено LLM и получено от неё, включая код из diff. Они полностью хранятся на вашей машине в `~/.opencodereview/`. OCR никуда их не загружает.

Если ваши ревью включают код, который не должен долго храниться, выполните одно из следующих действий:

- периодически удаляйте файлы сессий; или
- перенаправьте вывод `--audience agent --format json` во временный канал в CI и запускайте с временным `HOME`, чтобы JSONL не сохранялся.

Экспортёр OpenTelemetry — отдельная тема: как исключить содержимое prompt из экспортируемых трассировок, см. в разделе [Telemetry](../telemetry/).

## Когда просмотр сессий не подходит

- Для программной постобработки (CI, панели мониторинга) используйте `ocr review --format json --audience agent`. Просмотр сессий предназначен для людей, а не машин.
- Чтобы искать по множеству сессий, используйте `jq` непосредственно с JSONL-файлами. В UI пока нет поля поиска.

#### Markdown Review Principles
- Report only technically verifiable defects introduced or changed by the diff. Ignore wording, tone, spelling, formatting preferences, and other editorial concerns.
- Flag commands, flags, API names, configuration keys, file paths, or code examples only when repository content or the documented interface shows they are incorrect.
- Flag contradictions only when the changed text conflicts with another statement in the same document or with behavior that can be verified from the repository.
- Check local links, heading fragments, and image references when their target can be verified from repository content. Do not report external links as broken or outdated without direct evidence available during the review.

# Claude subscription authentication in Hermes

Checked on 2026-10-01 against first-party NousResearch and Anthropic documentation and source. No Hermes installation, user credential inspection, or live account request was performed for this research.

## Finding

The newly listed Hermes provider uses the official Claude Code executable for subscription authentication and inference. It does not implement its own subscription OAuth exchange followed by ordinary Client SDK requests. Its transport is a request-scoped CLI subprocess speaking `stream-json`; Hermes retains its agent loop. The plugin is maintained by NousResearch and marked official in the Hermes catalog, while its own name and documentation still say experimental. This catalog designation does not establish Anthropic certification. [Hermes catalog](https://hermes-agent.nousresearch.com/docs/plugins/claude-subscription-directsdk), [catalog manifest](https://github.com/NousResearch/hermes-agent/blob/main/plugin-catalog/claude-subscription-directsdk.yaml)

## Exact implementation

The catalog pins standalone repository `NousResearch/hermes-plugin-claude-subscription-directsdk` at `ef73726cfaf2fa0ee041e55572f406e2c24fed83`, version 0.3.0, requiring Hermes 0.21.4 or newer. The catalog lists it as added September 20 and re-pinned September 27, 2026. The pinned commit's GitHub API metadata gives committer time September 26, 2026, 20:18:11 UTC. [Catalog](https://hermes-agent.nousresearch.com/docs/plugins/claude-subscription-directsdk), [pinned commit metadata](https://api.github.com/repos/NousResearch/hermes-plugin-claude-subscription-directsdk/commits/ef73726cfaf2fa0ee041e55572f406e2c24fed83)

In the pinned `directsdk.py`, line 542 constructs the native command and line 548 spawns it with stdin/stdout pipes. It uses print mode, streaming JSON input/output, one logical native turn, disabled native tools and setting sources, strict MCP configuration, denied native approvals, and disabled native session persistence. Private files carry the system prompt and validated generation fields. Earlier user frames have querying disabled and require zero-turn acknowledgments; the final frame queries. Returned tools are checked against Hermes' inventory. These are version-sensitive replay mechanisms, rather than a general public arbitrary-history SDK contract. [Pinned transport source](https://github.com/NousResearch/hermes-plugin-claude-subscription-directsdk/blob/ef73726cfaf2fa0ee041e55572f406e2c24fed83/directsdk.py#L542), [replay source](https://github.com/NousResearch/hermes-plugin-claude-subscription-directsdk/blob/ef73726cfaf2fa0ee041e55572f406e2c24fed83/directsdk.py#L581)

The adapter also creates a loopback HTTP admission relay. Native Claude Code sends its own authenticated request through it; the relay forwards native authorization headers in memory, allows one Messages request, and rejects further attempts. The pinned relay can move a cache-control marker to a stable replay boundary. Therefore this is a CLI transport with a local HTTP relay, not a promise of unmodified request bodies or a plugin-owned OAuth client. [Pinned admission source](https://github.com/NousResearch/hermes-plugin-claude-subscription-directsdk/blob/ef73726cfaf2fa0ee041e55572f406e2c24fed83/admission.py#L122), [cache-boundary adjustment](https://github.com/NousResearch/hermes-plugin-claude-subscription-directsdk/blob/ef73726cfaf2fa0ee041e55572f406e2c24fed83/admission.py#L23)

Core support landed separately through Hermes PR 117451 on September 20, 2026, at commit `118984d7a02f8a8baec11255002cbbab7c202e06`. The earlier provider PR 105863 was closed after extraction, not merged as an in-tree provider. [Core PR](https://github.com/NousResearch/hermes-agent/pull/117451), [original PR](https://github.com/NousResearch/hermes-agent/pull/105863)

## Authentication ownership and earlier Hermes route

The new plugin delegates login and status to Claude Code. `directsdk_setup.py` invokes its auth commands and obtains the account's model picker through initialization. The plugin documentation says it never opens, copies, or refreshes credential files; the CLI owns these. [Pinned setup source](https://github.com/NousResearch/hermes-plugin-claude-subscription-directsdk/blob/ef73726cfaf2fa0ee041e55572f406e2c24fed83/directsdk_setup.py#L53), [plugin README](https://github.com/NousResearch/hermes-plugin-claude-subscription-directsdk#login-and-select)

Hermes also has a separate native Anthropic credential path. `agent/anthropic_credentials.py` resolves environment tokens, Hermes-owned grants, and borrowed Claude Code credentials, and implements refresh plus durable write-back. Its existence must not be confused with the new DirectSDK plugin's authentication ownership. This research does not establish Anthropic endorsement of that separate direct-token route. [Hermes credential source](https://github.com/NousResearch/hermes-agent/blob/main/agent/anthropic_credentials.py)

## Anthropic support and remaining uncertainty

Anthropic's help article is dated June 16, 2026. Its June 15 update pauses previously announced Agent SDK billing changes and says SDK, print-mode CLI, and third-party app usage continue to consume subscription limits. The article explicitly preserves the proposed monthly-credit details as historical material; those proposed credits must not be described as currently available. [Current plan article](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)

Claude Code's authentication documentation supports subscription sign-in for Pro, Max, Team, and Enterprise accounts. Invited Team users sign in with their own claude.ai accounts. On Windows, the CLI manages its credential file under the user profile or chosen configuration directory. Account entitlement and administrator policy still control access. [Official authentication documentation](https://code.claude.com/docs/en/authentication)

The current Agent SDK overview describes the SDK as a library that runs Claude Code, and recommends the CLI subprocess interface for other languages. The official Python SDK source confirms a subprocess with streaming JSON. However, the overview and quickstart still contain an approval condition for developers offering claude.ai login in products. This coexists with the help article's explicit acknowledgment of third-party subscription SDK usage. These sources do not resolve every redistribution or hosted-product case, nor establish blanket official support for extracting subscription tokens into the Go Client SDK. [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview), [SDK quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart), [official Python subprocess transport](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/transport/subprocess_cli.py)

For this local OCR integration, the evidence supports keeping subscription sign-in, refresh, and provider requests inside the official Claude Code runtime. Direct Client SDK OAuth through the Anthropic Console is a different credential and billing route. This is an implementation inference from the inspected sources, not a claim of Anthropic certification of OCR.

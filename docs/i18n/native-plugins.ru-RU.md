# Нативные плагины OCR

[English](../native-plugins.md) | [简体中文](native-plugins.zh-CN.md) | [日本語](native-plugins.ja-JP.md) | [한국어](native-plugins.ko-KR.md) | [Русский](native-plugins.ru-RU.md)

OCR поддерживает размещение нативных плагинов через свой инсталлятор, реестр и среду выполнения, предоставляя правила код-ревью (Review Rules) и контекстные инструменты MCP. Эти пакеты используют манифест `ocr-plugin.json` и не зависят от интеграций, подключающих OCR в сторонние кодовые агенты.

Границы модулей, диаграммы жизненного цикла и рекомендуемый порядок проверки кода описаны в [Руководстве по архитектуре нативных плагинов](../plugin-architecture.md).

## Поддерживаемые источники установки и ввод URL

Частый вопрос при начале работы: **Какие источники поддерживаются и поддерживается ли ввод через URL?**

`ocr plugin install <source>` принимает публичные URL GitHub, HTTPS-архивы, локальные каталоги и архивы. `ocr plugin add <source>` использует те же форматы, но накладывает дополнительные ограничения на источники проекта:

- Локальный источник должен находиться внутри целевого репозитория и записывается как нормализованный путь `./`. Абсолютный путь внутри репозитория допустим; внешний каталог или архив отклоняется.
- HTTPS-источник проекта должен иметь постоянный URL без параметров запроса, включая пустой `?`. Глобальная установка допускает параметры запроса, но скрывает их в выводе команд управления.
- `--repo` команды `add` задает целевой проект. Если текущий каталог оболочки отличается, используйте абсолютный путь к источнику.

### Поддерживаемые типы источников

OCR поддерживает четыре основных типа источников:

1. **Публичные репозитории GitHub (URL)**
   - **Корень репозитория**: `https://github.com/OWNER/REPO`
     Устанавливает пакет, расположенный в корне репозитория.
   - **Ветка или тег (с возможностью указания подкаталога)**: `https://github.com/OWNER/REPO/tree/REF/PATH`
     Например: `https://github.com/example/monorepo/tree/v1.2.0/plugins/security-rules`
   - **SHA коммита (неизменяемая ревизия)**: `https://github.com/OWNER/REPO/tree/FULL_40_CHAR_COMMIT_SHA/PATH`
     Напрямую указывает на конкретный 40-значный хэш коммита.
   - *Как это работает*: Если указана ветка или тег, OCR обращается к GitHub API для разрешения ссылки в точный 40-значный SHA коммита (если в URL уже содержится 40-значный SHA, запрос к API пропускается). Затем OCR скачивает tar.gz-архив репозитория с `codeload.github.com` в изолированный временный каталог и извлекает целевой каталог плагина.

2. **Удаленные HTTPS-архивы (URL)**
   - **HTTPS tar.gz архивы**: `https://example.com/team-review.tar.gz`
   - **HTTPS ZIP архивы**: `https://example.com/team-review.zip`
   - **Релизные ассеты**: `https://github.com/OWNER/REPO/releases/download/v1.0.0/plugin.tar.gz`
   - *Как это работает*: OCR скачивает файл по HTTPS, проверяет сигнатурные байты (gzip: `0x1f 0x8b`, ZIP: `PK`), благодаря чему расширение файла в URL не обязательно, и распаковывает содержимое в изолированную песочницу с проверкой лимитов размера.

3. **Локальные каталоги (Path)**
   - Локальный относительный или абсолютный путь к каталогу, содержащему `ocr-plugin.json` в корне:
     ```text
     ocr plugin install ./examples/ocr-plugins/review-checklist
     ocr plugin install /opt/company-plugins/code-style
     ```
   - OCR проверяет манифест и содержимое, после чего копирует снимок в локальное хранилище плагинов.

4. **Локальные архивы (Path)**
   - Локальные файлы `.tar.gz` или `.zip`:
     ```text
     ocr plugin install ./team-review.tar.gz
     ocr plugin install ./team-review.zip
     ```
   - Распаковываются в изолированный каталог, проверяются на целостность и сохраняются в хранилище.

### Неподдерживаемые и запрещенные источники

Для обеспечения детерминированного выполнения, воспроизводимости блокировок проекта и безопасности системы следующие источники **не поддерживаются**:

- **Обычные HTTP URL (`http://`)**: Строго требуется HTTPS. Незащищенные соединения и перенаправления с понижением до HTTP отклоняются.
- **URL с учетными данными или фрагментами**: URL с userinfo (например, `https://user:password@...`) или фрагментами (`#...`) отклоняются.
- **Каталоги Marketplace и JSON-индексы устаревшего формата**: Централизованный поиск по каталогу (`ID@market`) удален в пользу прямой установки пакетов.
- **Прямые Git SSH URL (`git@github.com:...`)**: Клонирование по чистому протоколу SSH Git не поддерживается. Используйте публичные HTTPS URL или архивы.
- **Символические ссылки, жесткие ссылки, файлы устройств и сокеты**: Для предотвращения атак обхода каталогов и повышения привилегий архивы, содержащие симлинки или специальные файлы, строго отклоняются при распаковке.
- **Имена локальных файлов со знаком `@`**: Простые пути со знаком `@` отклоняются во избежание путаницы с идентификаторами старых каталогов. Используйте явные пути (например, `./plugin@1.0.tar.gz`).

### Ограничения ресурсов и архивов

Для защиты от «архивных бомб» и исчерпания ресурсов установлены лимиты:
- **Максимальный размер манифеста**: 1 МиБ (`ocr-plugin.json`).
- **Максимальный размер скачиваемого архива**: 32 МиБ.
- **Максимальный размер распакованного содержимого**: 64 МиБ.
- **Лимит потока распаковки tar.gz**: 72 МиБ (включая заголовки и метаданные).
- **Максимальное число файлов в пакете**: не более 4 096.
- **Максимальный размер файлов конфигурации проекта**: 4 МиБ (`plugins.json` и `plugins.lock.json`).

## Полный справочник CLI-подкоманд

Вся функциональность сгруппирована под командой `ocr plugin` и разделена на **управление глобальными плагинами пользователя** и **управление плагинами проекта**, а команда `ocr mcp list` служит для инспекции инструментов.

```text
ocr plugin <command> [flags]
```

### Подкоманды управления глобальными плагинами

Глобальные плагины хранятся в `~/.opencodereview/plugins`. Будучи включенными, их правила и MCP-инструменты автоматически применяются ко всем проверкам и сканированиям текущего пользователя во всех репозиториях (если в репозитории не объявлены плагины проекта).

#### 1. `ocr plugin install <url|path>`
Загружает, проверяет и регистрирует пакет плагина из URL или локального пути, создавая изолированный снимок.

- **Аргументы**: `<url|path>` (URL GitHub, HTTPS URL архива, локальный каталог или архив).
- **Флаги**:
  - `--enable`: Автоматически включить плагин сразу после установки.
  - `--dry-run`: Скачать и проверить пакет без сохранения и включения, выведя предварительный отчет.
  - `--plugin <id>`: Выбрать конкретный идентификатор плагина, если источник содержит несколько плагинов.
  - `--json`: Вывод результата в формате JSON.
- **Принцип безопасности**: Установка выполняет только копирование файлов и валидацию манифеста; она **никогда не запускает код плагина, установочные скрипты или сборщики пакетов**.

#### 2. `ocr plugin list`
Выводит глобально зарегистрированные плагины в столбцах `ID`, `VERSION`, `STATE` и `CAPABILITIES`. Источники доступны через `ocr plugin show <id>` или `ocr plugin list --json`. Команда `ocr plugins list` эквивалентна; `ocr plugins` без подкоманды показывает справку.

- **Флаги**: `--json` (вывод в виде массива JSON).

```text
ID                VERSION  STATE     CAPABILITIES
review-checklist  1.0.0    disabled  1 rule packs, 0 MCP servers
```

#### 3. `ocr plugin show <id>`
Отображает подробную информацию об установленном плагине: каталог снимка, список правил, предоставляемые MCP-серверы и требования к версии OCR.

- **Аргументы**: `<id>` (идентификатор плагина).
- **Флаги**: `--json`.
- **Защита конфиденциальных данных**: Аргументы команд MCP, переменные окружения, заголовки авторизации и параметры URL автоматически скрываются при выводе.

#### 4. `ocr plugin update <id>`
Обновляет установленный плагин из его исходного источника с сохранением текущего статуса активности.

- **Аргументы**: `<id>` (идентификатор плагина).
- **Флаги**:
  - `--source <url|path>`: Заменить сохранённый источник. Поддерживаются те же HTTPS/GitHub URL, локальные каталоги и архивы ZIP/tar.gz, что и для `install`. ID пакета должен совпадать с ID установленного плагина.
  - `--accept-permissions`: Явно подтвердить добавление или изменение деклараций выполнения MCP.
  - `--json`: Вывод результата в формате JSON.
- **Контроль безопасности выполнения**: Если новая версия плагина **добавляет новый MCP-сервер** или **изменяет команды, аргументы, переменные окружения или транспорт существующего сервера**, OCR прерывает обновление с ошибкой (`PLUGIN_EXECUTION_CHANGED`). Пользователь должен проверить изменения и явно выполнить:
  ```sh
  ocr plugin update <id> --accept-permissions
  ```

Если токен загрузки истёк или адрес пакета изменился, укажите новый источник:

```sh
ocr plugin update my-plugin --source "https://plugins.example.com/download.php?token=NEW_TOKEN"
```

После успешного обновления следующие вызовы `update <id>` используют новый источник, включая параметры запроса URL. Состояние включения сохраняется. При ошибке загрузки, проверки или подтверждения прав прежний пакет и его источник остаются без изменений. Если требуется подтверждение, повторите команду одновременно с `--source` и `--accept-permissions`.

HTTPS URL загрузки может содержать параметры запроса и не обязан иметь расширение архива, если ответ содержит корректный архив плагина. Полный URL сохраняется локально; параметры запроса скрываются в выводе команд управления, но не шифруются при хранении. Эта команда обновляет глобальные установки. Зависимости проекта управляются через `plugin add` и `plugin lock`.

#### 5. `ocr plugin enable <id>`
Включает плагин. Его правила ревью и инструменты MCP будут подключаться к последующим запускам `ocr review` и `ocr scan`.

#### 6. `ocr plugin disable <id>`
Отключает плагин. Пакет сохраняется на диске, но не загружается при ревью.

#### 7. `ocr plugin remove <id>`
Отменяет регистрацию и удаляет плагин. Активные сессии ревью продолжают использовать ранее созданные снимки до своего завершения.

### Подкоманды управления плагинами проекта

Для командной работы и CI/CD критически важна воспроизводимость: использование идентичных версий плагинов и прозрачное разграничение прав на выполнение. Плагины проекта описываются в `.opencodereview/plugins.json` (декларация) и фиксируются в `.opencodereview/plugins.lock.json` (lock-файл).

Когда в репозитории присутствуют файлы плагинов проекта, OCR переходит в **режим изоляции проекта**: загружаются только зафиксированные плагины проекта, а глобальные плагины полностью игнорируются.

#### 1. `ocr plugin add <source>`
Добавляет зависимость плагина в текущий проект. Разрешает источник, обновляет `.opencodereview/plugins.json` и фиксирует артефакт текущей платформы в `.opencodereview/plugins.lock.json`.

- **Флаги**:
  - `--plugin <id>`: Выбор плагина из источника с несколькими пакетами.
  - `--repo <path>`: Путь к корню проекта.

#### 2. `ocr plugin lock`
Разрешает зависимости из файла декларации для текущей операционной системы и архитектуры (`GOOS/GOARCH`) и генерирует либо обновляет lock-файл.

#### 3. `ocr plugin sync`
Устанавливает точные снимки артефактов, зафиксированные в lock-файле.

- **Флаги**:
  - `--frozen`: **Обязательный флаг**. Требует строгого соответствия декларации и lock-файла, запрещая автоматическое обновление версий.
  - `--offline`: Автономный режим — использовать только локальный кэш снимков или локальные файлы репозитория.
  - `--repo <path>`: Путь к корню проекта.
- **Безопасность**: Команда `sync` только копирует снимки и **ни при каких условиях не выполняет код плагинов и не выдает прав на запуск**.

#### 4. `ocr plugin trust`
Предоставляет локальное разрешение для текущего lock-файла проекта. Оно требуется для всех объявленных MCP-серверов, включая удаленные подключения. Пакетам только с правилами разрешение на выполнение не нужно.

- **Флаги**:
  - `--revoke`: Отозвать локальное доверие на выполнение.
  - `--repo <path>`: Путь к корню проекта.

Разрешение хранится вне репозитория в `~/.opencodereview/plugins/projects/<project-hash>/trust-<lock-id>` и привязано к каноническому пути проекта, содержимому lock-файла и платформе. При изменении lock-файла требуется новое разрешение. Команды `add`, `lock` и `sync` его не выдают. Для отзыва используйте `ocr plugin trust --revoke`.

#### 5. `ocr plugin project`
Проверяет соответствие декларации и lock-файла и выводит содержимое lock-файла, включая платформы. Статус установки и разрешений здесь не отображается. Используйте `ocr plugin preflight --json` для их проверки или `ocr mcp list --json` для просмотра конфигурации MCP и разрешений.

#### 6. `ocr plugin preflight`
Выполняет предварительную проверку перед запуском ревью или в пайплайнах CI: проверяет наличие всех пакетов, совпадение контрольных сумм, совместимость версий и наличие доверия на выполнение.

- **Флаги**:
  - `--fingerprint`: Вычисляет детерминированный цифровой отпечаток проверенного lock-файла и платформы (используется для кэширования инкрементального ревью).
  - `--repo <path>`: Путь к корню проекта.
  - `--json`: Вывод в формате JSON.

### Команда инспекции инструментов MCP

#### `ocr mcp list`
Обеспечивает единое, безопасное представление всех сконфигурированных MCP-серверов: из пользовательского файла конфигурации (`~/.opencodereview/config.json`), глобальных плагинов и плагинов проекта.

```sh
ocr mcp list
ocr mcp list --repo /path/to/project --json
```

- **Поля вывода**: Имя сервера (`plugin/PLUGIN_ID/SERVER`), источник (`user_config`, `global_plugin`, `project_plugin`), транспорт (`stdio`, `remote`), статус конфигурации и статус авторизации.
- **Безопасность**: Команда только читает манифесты. Она **никогда не запускает процессы серверов, не выполняет установочные хуки, не устанавливает сетевые соединения и не обращается к ключам LLM**.

| Статус | Значение |
| --- | --- |
| `configured` | Сервер выбран и авторизован; готов к вызову при ревью |
| `disabled` | Глобальный плагин отключен |
| `incompatible` | Не соблюдены требования к минимальной версии OCR |
| `authorization_required` | Снимок установлен, но доверие `ocr plugin trust` не предоставлено |
| `server_name_conflict` | Имя сервера плагина конфликтует с сервером из ручной конфигурации |

## Типовые сценарии работы

### Работа с глобальными плагинами

```sh
# 1. Предварительный просмотр
ocr plugin install https://github.com/example/team-rules --dry-run

# 2. Установка и включение
ocr plugin install https://github.com/example/team-rules --enable

# 3. Проверка установленных компонентов
ocr plugin show team-rules
ocr mcp list

# 4. Запуск ревью (правила и инструменты применяются автоматически)
ocr review

# 5. Обновление с подтверждением прав
ocr plugin update team-rules --accept-permissions
```

### Плагины проекта и CI/CD

```sh
# 1. Добавление зависимости и коммит lock-файла
ocr plugin add https://github.com/example/security-pack
git add .opencodereview/
git commit -m "chore: add security review plugin"

# 2. Синхронизация точных версий в CI или на машине разработчика
ocr plugin sync --frozen

# 3. Инспекция и предоставление доверия на исполнение MCP
ocr plugin project
ocr plugin trust

# 4. Проверка перед запуском
ocr plugin preflight

# 5. Запуск ревью
ocr review
```

### GitHub Actions

Добавьте следующие параметры в `with` существующего шага OCR Action:

```yaml
project_plugins: 'true'
allow_plugin_exec: 'false'
```

Зафиксируйте версии Action и CLI с поддержкой `plugin sync --frozen` и `preflight --fingerprint`; старые релизы не поддерживают этот процесс. Action устанавливает зафиксированные пакеты до настройки учетных данных модели. Включайте `allow_plugin_exec: 'true'` только после проверки объявлений MCP, в том числе удаленных подключений. Это разрешение действует для текущего запуска; lock-файл сам по себе выполнение не разрешает.

Правила, декларация, lock-файл и локальные пакеты должны находиться в доверенной копии политики. По умолчанию используется базовый коммит PR; при запуске из комментария он определяется через PR API. Параметр `policy_sha` позволяет указать полный SHA другого доверенного коммита. Из PR head берется diff, но не политика плагинов.

Lock-файл должен содержать ОС/архитектуру runner. Выполните `ocr plugin lock` на каждой целевой платформе и закоммитьте результат. При неизменной декларации записи других платформ сохраняются; при изменении декларации становятся недействительными. Сохраняйте одинаковые байты локальных пакетов при checkout, например через `eol=lf` в `.gitattributes`.

Каждый запуск использует новый частный домашний каталог OCR и проверяет содержимое пакетов и разрешения. Нативные программы имеют права runner и доступ к его окружению, включая учетные данные модели. Не восстанавливайте записи доверия из общего кэша. Изменение политики, идентичности плагинов или разрешений аннулирует контрольные точки инкрементального ревью.

Подробности: [пример настройки Action](../../examples/github_actions/README.md#project-plugins-in-ci).

## Спецификация создания пакета плагина

В корне каталога или tar.gz-архива размещается файл `ocr-plugin.json`:

```text
my-plugin/
├── ocr-plugin.json
├── rules.json
├── checks.md
└── server.mjs
```

Пример манифеста:

```json
{
  "schema_version": 1,
  "id": "team-review",
  "name": "Team Review",
  "version": "1.0.0",
  "description": "Командные правила ревью и инструменты контекста репозитория",
  "rules": ["rules.json"],
  "mcp_servers": {
    "context": {
      "type": "stdio",
      "command": "node",
      "args": ["${plugin_dir}/server.mjs"],
      "tools": ["team_repository_context"]
    }
  },
  "requires": {
    "ocr_min_version": "1.2.0",
    "features": ["rules", "mcp"]
  },
  "metadata": {
    "homepage": "https://example.com/team-review"
  }
}
```

### Файлы правил

Массив `rules` в манифесте содержит относительные пути `.json`. Каждый файл содержит массив `rules` в формате OCR; отдельное правило может ссылаться на Markdown внутри пакета. Пакеты правил не могут задавать `include` или `exclude`. Их правила добавляются к существующей конфигурации.

```json
{"rules":[{"path":"**/*","rule":"checks.md"}]}
```

Размер каждого JSON-файла правил ограничен 512 КиБ, а ссылки должны оставаться внутри пакета. Полный пример: [review-checklist](../../examples/ocr-plugins/review-checklist).

### Поля манифеста

- `schema_version` должен быть `1`. Неизвестные операционные поля и дублирующиеся ключи JSON отклоняются.
- `id` содержит до 64 символов: строчные буквы, цифры, точки, подчеркивания и дефисы; первый и последний символы — буква или цифра. Зарезервированные имена устройств Windows запрещены.
- `name` и `version` не могут быть пустыми. Требуется хотя бы один пакет правил или MCP-сервер.
- `rules` содержит относительные пути `.json`; формат описан выше.
- `stdio` (по умолчанию) в `mcp_servers` использует `command`, `args`, `env` (`KEY=VALUE`) и список разрешенных `tools`. `remote` использует HTTP/HTTPS `url`, `headers` и `tools`. Для передачи учетных данных выбирайте HTTPS. Отдельно для загрузки пакетов HTTPS обязателен.

### Поддерживаемые плейсхолдеры

В полях `command`, `args` и `env` доступны плейсхолдеры:
- `${plugin_dir}`: абсолютный путь к каталогу установленного снимка плагина.
- `${os}`: имя ОС (`linux`, `darwin`, `windows`).
- `${arch}`: имя архитектуры (`amd64`, `arm64`).
- `${exe}`: `.exe` для Windows, пустая строка для Unix-систем.

### Упаковка для распространения

При сборке плагина, содержащего исполняемые файлы или скрипты под Linux/macOS, установите бит исполняемости перед упаковкой (`chmod +x bin/server`). OCR автоматически сохраняет флаг исполняемости при распаковке tar.gz:

```sh
tar -czf team-review-1.0.0.tar.gz -C my-plugin .
```

## Модель безопасности и гарантии целостности

1. **Отсутствие выполнения кода при установке**: команды `install`, `sync`, `list`, `show`, `dry-run`, `lock` и `preflight` не исполняют код плагина.
2. **Детерминированные цифровые отпечатки**:
   - `archive_sha256`: хэш SHA-256 файла скачанного архива.
   - `content_sha256`: детерминированный хэш содержимого дерева файлов по алгоритму `ocr-package-tree-v1`.
3. **Барьер при изменении прав**: обновление глобального плагина с измененными параметрами запуска MCP требует явного подтверждения флагом `--accept-permissions`.
4. **Изоляция доверия проекта**: права на запуск хранятся за пределами репозитория; свежий клон проекта не получает прав на выполнение без явной команды `ocr plugin trust`.
5. **Защита базового коммита в CI**: в GitHub Actions манифест плагинов и lock-файл всегда загружаются из базового коммита PR, предотвращая выполнение недоверенного кода из веток форков.

## Совместимость и требования к хосту

Поле `requires` необязательно. `ocr_min_version` требует полную семантическую версию, например `1.2.0`; сборка `dev` без сравнимой версии не удовлетворяет этому условию. `features` перечисляет обязательные возможности: эта версия поддерживает `rules`, `mcp` и `stdio-v1`. Неподдерживаемые требования отклоняются до выполнения. Не копируйте ненужные ограничения версии из примера.

Описательные метаданные помещаются в `metadata`. Неизвестные операционные поля и дублирующиеся ключи JSON отклоняются. Метаданные старого маркетплейса могут читаться для миграции, но установка из каталогов больше не поддерживается.

Рабочие процессы можно объединять с правилами и MCP. Их разрешение в проекте также привязано к lock-файлу. Добавление или изменение объявления выполнения рабочего процесса при глобальном обновлении требует `--accept-permissions`. Установка или включение сами по себе не выбирают процесс: нужен явный `--review-plugin ID`. См. [плагины рабочих процессов](review-workflow-plugins.ru-RU.md).

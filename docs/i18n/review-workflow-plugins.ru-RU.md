# Плагины рабочих процессов ревью (Review Workflow Plugins)

[English](../review-workflow-plugins.md) | [简体中文](review-workflow-plugins.zh-CN.md) | [日本語](review-workflow-plugins.ja-JP.md) | [한국어](review-workflow-plugins.ko-KR.md) | [Русский](review-workflow-plugins.ru-RU.md)

О взаимосвязи между установкой пакетов, правами на выполнение и адаптерами среды выполнения см. в [Руководстве по архитектуре нативных плагинов](../plugin-architecture.md).

Используйте рабочий процесс (workflow), когда для код-ревью требуется строгая последовательность этапов и специфические критерии завершения: например, сначала выполнить первичную инспекцию диффа, а на следующем этапе перепроверить каждое найденное замечание перед формированием итогового отчета. Пакет плагина объявляет эти этапы и валидирует результаты работы модели; OCR предоставляет дифф, правила, инструменты и бюджет токенов.

## Запуск примера single-pass

В среде, где доступен Python 3 как `python`, установите пример и выполните предварительный просмотр ревью для изменений в рабочей копии:

```sh
ocr plugin install ./examples/ocr-plugins/single-pass
ocr review --review-plugin single-pass --preview
```

При настроенном провайдере моделей и наличии изменений для проверки выполните:

```sh
ocr review --review-plugin single-pass --format json --output review.json
```

Этот пример состоит из одного этапа. Он запрашивает у модели найденные замечания и валидирует их до того, как OCR опубликует комментарии. Поле `review_plugin` в `review.json` содержит статус завершения и отчет. Сама установка не выполняет код пакета, а режим предварительного просмотра (`--preview`) не запускает Python и не отправляет запросы к модели.

Если в репозитории объявлены плагины проекта, добавьте пример в декларацию проекта и авторизуйте его согласно инструкциям ниже.

## Выбор и выполнение на уровне проекта

Для рабочего процесса, управляемого на уровне репозитория, объявите его с помощью `ocr plugin add <source>`, зафиксируйте `.opencodereview/plugins.json` и `plugins.lock.json`, затем установите через `ocr plugin sync --frozen`. Проверьте зафиксированный пакет и выполните `ocr plugin trust` для предоставления локального доверия перед вызовом `--review-plugin <id>`. Команда `ocr plugin preflight --json` проверяет целостность установленного содержимого, совместимость и статус доверия без запуска процесса и вызова модели. Если объявлены плагины проекта, выбор ограничен только зафиксированными пакетами проекта. Подробнее см. в [Руководстве по нативным плагинам OCR](native-plugins.ru-RU.md#project-plugins).

Плагин рабочего процесса управляет планом этапов, промптами, схемой завершения, валидацией и состоянием между этапами. OCR отвечает за дифф, правила, запуск модели и инструментов, сессии, учет токенов, публикацию комментариев и вывод.

Выбор рабочего процесса для одного запуска:

```sh
ocr review --review-plugin PACKAGE_ID --preview
ocr review --review-plugin PACKAGE_ID --format json --output review.json
```

Установка или включение плагина не активирует его рабочий процесс автоматически. Флаг `--preview` только считывает манифест без запуска процессов. При реальном запуске исполняемый файл плагина работает с локальными правами пользователя (аналогично локальному серверу MCP). При явном указании `--review-plugin` правила и MCP-серверы этого плагина подключаются к текущему запуску, даже если плагин глобально отключен.

## Конфигурация манифеста (Manifest)

```json
{
  "schema_version": 1,
  "id": "example-review",
  "name": "Example Review",
  "version": "1.0.0",
  "review": {
    "protocol": "stdio-v1",
    "command": "${plugin_dir}/bin/${os}-${arch}/reviewer${exe}",
    "args": ["--policy", "${plugin_dir}/policy.md"],
    "stages": ["inspect", "verify"]
  }
}
```

Поле `command` указывает путь к исполняемому файлу (запускается без оболочки shell). В командах и аргументах подставляются `${plugin_dir}`, `${os}`, `${arch}`, `${exe}` (`.exe` для Windows, пустая строка для Unix). Исполняемые среды из PATH (например, `python`) также поддерживаются. Пример на Python ожидает команду `python`. Если в системе доступен только `python3`, укажите `python3` в манифесте перед упаковкой.

Плагины могут объединять рабочие процессы, правила и инструменты MCP. Идентификаторы этапов уникальны; манифест может объявлять от 1 до 64 последовательных этапов.

Установленный снимок предоставляет правила и рабочий процесс для текущего запуска. Обновление пакета не меняет уже работающий снимок. Хостам, поддерживающим только старый эксперимент `engine`/`prompt`, требуется обновление. Хост читает старые установочные метаданные, чтобы такие пакеты можно было перечислить, удалить или обновить. Вывод помечает их как требующие обновления (`review.update_required` в JSON) и не показывает команду запуска. Попытка запуска требует сначала обновить пакет.

## Совместимость

Рабочие процессы могут задавать необязательные `requires.ocr_min_version` и `requires.features`, например `["rules", "mcp", "stdio-v1"]`. См. [требования к хосту](native-plugins.ru-RU.md#compatibility-and-host-requirements). Неподдерживаемые требования отклоняются до запуска процесса. API рабочих процессов экспериментальный. Существующие плагины `stdio-v1` продолжают использовать `begin`/`submit`; обязательного рукопожатия или перехода на JSON-RPC нет. Неизвестные поля оболочки ответа приводят к ошибке. Структуры `report` и аргументов завершения определяет плагин. Несовместимое изменение оболочки требует новой версии протокола или сообщения.

## Протокол stdio-v1

OCR запускает один процесс на группу файлов с рабочим каталогом в проверяемом репозитории. Процесс сохраняет состояние между этапами группы. Запросы и ответы — однострочные объекты UTF-8 JSON размером до 4 МиБ. На каждый запрос нужен ровно один ответ; диагностика направляется в stderr. Каждый ответ содержит `"version": 1`. Непустая строка `error` означает невозможность выполнить запрос и останавливает группу.

### Начало этапа (`begin`)

Перед каждым этапом OCR отправляет:

```json
{"version":1,"method":"begin","stage":"inspect","paths":["main.go"],"severities":["critical","high","medium","low"],"categories":["bug","security","performance","maintainability","test","style","documentation","other"]}
```

Плагин возвращает описание задачи и опциональный начальный отчет:

```json
{"version":1,"task":{"instructions":"Inspect the selected code.","input":"Check the public return contract.","completion":{"description":"Submit the result.","parameters":{"type":"object","properties":{"checked":{"type":"boolean"}},"required":["checked"]}}},"report":{"pending":["inspection"]}}
```

OCR добавляет instructions и input к обычному контексту diff и правил и сохраняет их при сжатии контекста. Оба поля, `instructions` и `input`, должны содержать непробельный текст, поскольку становятся отдельными сообщениями модели. Модель сохраняет доступ к контекстным инструментам OCR. Определение `task_done` берется из `completion`; прямой инструмент `code_comment` скрыт, чтобы публикация проходила через валидатор плагина.

Учетные данные модели не передаются в запросах протокола. Однако исполняемый файл наследует обычное окружение процесса, которое может содержать токены провайдера и настройки прокси. Он также может читать конфигурацию, доступную текущему пользователю. Изоляции выполнения в этом релизе нет; устанавливайте и выбирайте рабочие процессы только доверенных авторов.

### Отправка результатов моделью (`submit`)

Когда модель вызывает `task_done`, OCR пересылает аргументы без изменений:

```json
{"version":1,"method":"submit","stage":"inspect","arguments":{"checked":true}}
```

Ответ с принятием результатов должен содержать явные булевы флаги `accepted` и `complete`:

```json
{"version":1,"accepted":true,"complete":true,"report":{"checked":true},"comments":[]}
```

Структуру отчета и условия завершения определяет плагин. Ответ `accepted:true` с `complete:false` останавливает группу как незавершенную. Поле `feedback` сохраняется как причина незавершенности и не запускает исправление моделью. Принятые комментарии проходят обычную публикацию и фильтрацию, в том числе для незавершенной работы. Комментарии должны ссылаться на выбранный путь, содержать текст и использовать severity/category, переданные при `begin`. Остальные поля: `existing_code`, `suggestion_code`, `start_line`, `end_line`, `thinking`.

Для исправимой ошибки модели верните `accepted:false`, непустой `feedback`, последний `report` и не включайте комментарии. OCR возвращает обратную связь модели в пределах существующего лимита запросов. Плагин сам сохраняет корректные частичные результаты. Сбой процесса, некорректный ответ протокола и отсутствие обязательных булевых полей останавливают выполнение; они не повторяются как ошибки модели.

## Завершение и вывод результатов

Все объявленные этапы должны завершиться, даже если предыдущие не нашли проблем. Флаг `--effort` не сокращает план плагина. Действуют существующие настройки контекста, раундов инструментов и таймаутов; таймаут группы учитывает объявленное количество этапов. Если пользователь задает бюджет токенов, оставшиеся этапы делят неиспользованный остаток; дополнительный общий лимит не вводится.

JSON-массив `review_plugin` содержит `plugin`, `group`, `stage`, `complete`, необязательный `token_limit`, определяемый плагином `report` и ошибку выполнения `error`. При последующем сбое модели или процесса сохраняется последний полученный отчет. Каждый завершенный или прерванный этап сохраняет запись `plugin_review` в сессии, в том числе при текстовом выводе. Она доступна в массиве `review_plugin` команды `ocr session show SESSION_ID --json`. Если ответ не содержит `report`, предыдущий отчет сохраняется. Незавершенная обязательная работа попадает в учет покрытия и приводит к ненулевому коду выхода CLI. Поведение обычного ревью при завершении не меняется.

Для ревью с рабочим процессом требуется новый вызов. Флаг `--resume` пока не восстанавливает произвольное состояние процесса. JSON и записи сессии остаются доступны для просмотра.

Реализация на Python доступна в [примере single-pass](../../examples/ocr-plugins/single-pass). [Behavior Review](https://github.com/Qiyuanqiii/ocr-behavior-review) — независимый исполняемый плагин с тремя этапами и сохранением доказательств.
